## 1. Epic-01 · 城市经营垂直切片闭环

### 1.1 定义（逐字承接概念 §5.2）

```
空地（有限网格）
  → 划 3 类分区，铺 1 类道路连成通勤网
  → 拨一个周期的预算（收入 / 建设 / 维护 / 结余）
  → 推若干 tick，观察满意度 4 因子的变化与议题出现
  → 用「诊」定位一次问题并「调」修正
  → 市政周期结算：满意度达标 / 未达标
  → 达标则 V9 解锁下一块地，进入第二轮；未达标可回退重试
```

### 1.2 切片内必须有（缺一不可，概念 §5.2）

1. **七条规则全贯通**：R1 有限网格 + R2 分区 + R3 预算 + R4 通勤图 + R5 tick + R6 满意度 4 因子 + R7 周期结算，**不允许先做半套**。
2. **V1→V9 全动词可达**，尤其 **V2 诊不可省**。
3. 一次完整的「**失败—诊断—修正—见效**」体验（验证心流与因果可读性）。
4. **手机竖屏单手可完成**；本地存档可断点续玩。

### 1.3 切片外明确没有（不得混入 DoD）

无公共交通、无政策卡、无地价、无多道路等级、无危机事件、无跨设备、无折叠屏双栏、无季节昼夜、无成就、无分享、**无 ×1×2×4 自动播放**（OD-2 A）、无具象个体市民（OD-3 A）、无无尽地图（OD-4 A）。
> 切片验收看「**闭环通不通**」，不看「内容多不多」（概念 §5.2）。

### 1.4 架构对 Epic 的额外约束（本文补充，不改设计口径）

- 全部 Story 走 `control-manifest.md` §1 一页控制规则；每个 Story 的验收条件须可在**零平台特性、手机竖屏、预览版 API 降级路径**下验证（G12）。
- 首个 Epic 结束前完成**第一次真机性能基线校准**（S-12），把美术圣经 §9.4 建议基线逐条测量记录；**不擅自冻结为硬指标**。

## 4. 逐 Story 详表

### S-01 · 工程链路与平台适配骨架

- **目标**：把「Cocos Creator 3.x → HarmonyOS NEXT 导出 → DevEco Studio 打包 HAP」链路跑通；钉定 NAPI/XComponent 边界与六个抽象接口；给预览版 API 的**降级默认值**。
- **交付**：可启动的空场景 HAP；构建锁（Cocos 小版本 / SDK·API / DevEco 版本）；`PlatformAdapter` 六个接口定义 + 降级实现（安全区保守留白、形态默认 folded、文件 IO 走 `ISaveStorage`）。
- **验收条件**：
  1. 真机（手机竖屏）启动空场景，XComponent Surface 正常渲染 2:1 等距网格。
  2. `onForeground/onBackground`、surface 销毁重建、折叠态切换均不崩溃、**不重置任何状态**。
  3. 折叠态 / 安全区接口**读取失败**时，降级路径生效（回退单栏、手动留白 24dp、关键控件不压中央铰链带）。
  4. 静态检查：业务层零 HarmonyOS SDK import；权限声明无后台保活 / 精确闹钟。
  5. 构建锁存在，`engineVersion` 可写入存档头。
- **依赖**：无前置 Story。上游 GDD：无（架构自身）；美术圣经 §9.3 图集约束仅作输入。
- **H1~H4 阻塞**：**否**。验证的是「引擎链路 + 降级路径」本身，**不是实现 H1/H2/H3 特性**；H4 无实现。任何平台特性仍须真机验证后方可排期。
- **关联**：ADR-001 A1–A6；评审门 G1 / G2 / G8 / G12；控制规则 §1.1。

### S-02 · 数据层 schema 与配置表接入

- **目标**：定义网格 / 分区 / 路网 / 预算 / 满意度因子的 schema 与 `schemaVersion`；静态配置表加载机制与 `configHash`；分区类型**可扩展枚举**（3 类 MVP 激活集 + 预留）。
- **交付**：`Schema` / `ConfigStore`；一份固定 32×32 网格初始状态（起始解锁子集建议 16×16，由 GDD 钉定）；配置表加载 + hash 计算。
- **验收条件**：
  1. 可加载并序列化 / 反序列化一份 32×32 初始状态，数据层**零引擎 / 零平台依赖**，可脱离真机单测。
  2. 满意度 4 因子公式 / 权重**只从配置表注入**，代码中无硬编码数值；配置变更必升 `configHash`。
  3. 分区类型由配置驱动，增 / 减分区不改动数据层与加载层代码（化解冲突 X-2 的架构预留）。
  4. 网格上限固定 32×32；>32×32 的加载被显式拒绝或触发重评标记。
- **依赖**：S-01。上游 GDD：地图与分区 / 满意度 / 经济预算 / 目标进度（配置表内容）。
- **H1~H4 阻塞**：**否**（纯数据层）。
- **关联**：ADR-002（不越界定义公式）；主文档 §0.2 / §6.4 / §10.2；评审门 G3。

### S-03 · 确定性 tick 结算引擎（R1–R7 贯通）

- **目标**：实现 ADR-002 的 P0~P8 结算 pipeline，一次结算贯通七条规则；纯函数、确定性、零热路径分配。
- **交付**：`CommandQueue` / `InputGate` / `TickPipeline`（P0~P8）/ 可注入的满意度聚合器接口；`BudgetRejected` 事件。
- **验收条件**：
  1. 同一 (S_t, 命令, 配置) 连续结算 / 跨会话回放结果**逐字节一致**（ADR-002 A1）。
  2. 默认暂停下渲染帧循环推进任意帧数，模拟状态与 `tickId` **不变**；仅 V6 触发一次结算。
  3. P0~P8 阶段顺序固定可观测；**R1~R7 各有对应阶段**；P3 服务覆盖复用 P2 通勤图，代码库无「纯半径叠 buff」分支（概念 P3 否决项）。
  4. 连点两次「结束本日」不产生两次结算；结算期间 pending 命令排队不半应用。
  5. P7 周期判定**只标记「可回退重试」，无「失败终局」分支**（OD-1 A）。
  6. 静态检查：模拟层零平台 / 零渲染依赖、无墙上时钟、无原生随机、零热路径分配。
- **依赖**：S-02。上游 GDD：全部 5 个系统（R1~R8；公式 / 权重 / 建筑表 / 周期 tick 数由 GDD 提供）。
- **H1~H4 阻塞**：**否**（纯 TS 模拟层）。
- **关联**：ADR-002 A1–A3、A9；评审门 G3 / G9；控制规则 §1.2；**DoD D-1**。

### S-04 · 通勤图求解与结算性能基准

- **目标**：网格图 → 合并分区块 OD 需求 → 流量分配 → 链路通行时间 / 容量利用率；建立结算耗时测量钩子。
- **交付**：`TrafficGraphSolver`；32×32 满网格基准场景加载脚本（后续）；耗时采集钩子。
- **验收条件**：
  1. 分区块合并（B≤64 量级），**代码库无逐格 OD 矩阵**（概念 Won't「逐车个体仿真」/ ADR-002 A6）。
  2. D1 通勤潮汐 / D2 拥堵负反馈在结算中可观测（容量饱和 → 覆盖因子恶化）。

## 6. H1~H4 阻塞结论专节

> **12 条 Story 全部标注「否」**，这不是遗漏，是架构结论。逐条理由：

| 特性 | 档位 | 为何不阻塞首个 Epic |
| --- | --- | --- |
| **H1 秒启卡片** | Could，只读不可操作 | 垂直切片是「进游戏后的闭环」，桌面卡片属「不进游戏也能读」的前移能力；概念 §5.2 切片外明确「无分享 / 无卡片」。`IFeatureFlags` 预留、默认关，**须真机验证后方可排期** |
| **H2 折叠屏双栏** | Should（平台特性中优先级最高） | 首个 Epic 的硬要求是「**手机竖屏单手可完整通关**」（概念 §5.2）。S-01 的保守安全区 + S-08 的弹性布局 / 单栏回退**已足以在预览版接口不稳时跑通**；双栏只是「信息密度增益」，回退不丢功能。S-12 把折叠展开态纳入**性能测量矩阵**，但不实现双栏特性 |
| **H3 跨设备流转** | Could | 主文档 §11.4 已论证：OD-2/OD-4 拍板 A 后状态是「静止、离散、可完全序列化的短快照」，迁移容易但没必要；且依赖预览版分布式 API + 冲突消解。**仅预留 `ISaveStorage` 能力位，不实现、不排期**（S-10） |
| **H4 分布式多机同局** | **Won't** | 概念 §2.3 排除 Fellowship / Competition；引入实时同步 / 权威状态 / 冲突消解会冲垮 lean 范围。架构**不预留、不评估、无对应 Story** |
