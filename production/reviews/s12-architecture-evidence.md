## 第一层 · 断言库自证 —— **已达成**

本层证明的是：**断言函数的行为正确**。仅此而已。

| 证据 | 内容 | 位置 |
| --- | --- | --- |
| 热区基线 | `MIN_TAP_TARGET_DP = 48`（华为 2.1.3.3 推荐值 48vp；40vp 仅合规底线） | `src/ui/hud/a11y.ts:34` |
| 边界钉死 | 47 抛 / 48 过（含等号）+ `MIN-1` 必抛（防 `>=` 写反） | `s12-a11y-gate.test.ts` AC-A05-1 |
| 双向棘轮 | `!== 40`（取官方必须下限 = 擅自放宽，拒收）+ `!== 44`（旧基线回退，拒收） | 同上 |
| 间距断言修复 | `assertSpacing` 原为**永真断言**（判 `tapTargetDp` 而非间距 / `8 < 44` 结构不可达 / `length-1` off-by-one）→ 改为真判 `gapDp`，未声明显式抛错 | `a11y.ts:100-118` |
| 门禁有牙齿 | 阈值类突变（4.5→15）与结构类突变（交集非空）均能变红，撤回后复绿 | gate 自证两段 |
| 令牌安全 | `textSafe` 由 `contrastRatio(color, BASE.canvas) >= 4.5` 实算（非手写）；inkWeak 2.31:1 → false；扫描器对合成违规必报红 | `token-text-safety.test.ts` TS-1/TS-5 |

**本层不能证明的**：任何控件的真实热区、任何真机上的物理行为。

## 第二层 · 控件达标 —— **未达成（结构性空洞，自 S-08 起即如此）**

核心事实（已多流独立复核）：

1. **`A11yControl` 在 `src/` 内零个对象字面量赋值**。唯一赋值点是 `tests/unit/hud-a11y.test.ts` 的 15 处 fixture（手写声明值，如 `tapTargetDp: 56`）。
2. 四个断言函数（`assertTapTarget` / `assertSpacing` / `assertReducedMotionDualChannel` / `assertReachableAtTier`）的运行时输入**全部是测试手写 fixture**，不是引擎布局出来的真实矩形。
3. 因此 `control-manifest.md:90` 那条 ✅ **从来没有可举证的证据源**——44dp 时代同样如此。这是自 S-08 建断言库起就存在的结构性空洞，**非本次 44→48 上调造成**。
4. `AC-A05-2` 的解封硬条件（gate 采纳 a11y-api 异议后写死）：④ `grep -rn "assertSpacing(" src/ | wc -l` ≥ 1；⑤ `grep -rn "gapDp" src/ | grep -v a11y.ts` 非空。**当前两条均不满足**（实测：调用点 0 / 生产侧零赋值）。

重验门槛（三条同时成立才算「生产侧就位」，缺一即为填空式满足）：

1. `src/` 内存在逐控件 `tapTargetDp` / `gapDp` 声明；
2. 全量控件通过 48dp 断言（含 47 抛 / 48 过边界）；
3. **声明来源须是布局计算或统一控件定义表，不得手写常量**——「在 src 里写死一个 `tapTargetDp: 48` 的数组」来满足 ①，仍属伪造证据。

## 第三层 · 真机达标 —— **未达成（EX-03 准出阻塞）**

物理命中区间是否重叠、触摸容差、系统手势边缘内缩、厂商 ROM 显示/字体缩放、vp→px 实际换算——**全部未验**。关联未关闭项：

- **EX-01**：`SM-W1-04` 生命周期（真机半侧）；
- **EX-02**：S-06 ③b 纹理格式探测写入校准记录；
- **K-4**：沙箱 KV、HAP 权限模型（存档层「内存模拟介质」与真实持久化的差距）。

测量方法论已备好：`production/calibration/device-calibration-runbook.md`（745 行）+ `raw-measurement-sheet.md`（235 行），§10.1 七行基线逐字一致、**不冻结任何数字**。已裁定事项：L2 ≤150 放宽口径本轮不适用（单栏大视口不占信息密度前提），≤150 仅作上报触发线。

## §4 48dp 与 8dp 不同源（防同句误读）

`control-manifest.md:90` 把「热区 ≥48dp、间距 ≥8dp」同句并列，易被误读为同源。**必须拆开**：

- **48dp**：华为《通用应用 UX 体验标准》**2.1.3.3**，等级「**必须**」，原文「至少为 48vp×48vp（**推荐**），不得小于 40vp×40vp（**必须**）」。**本项目取推荐值 48dp，属收紧**；40vp 仅为官方合规底线，**不得作为本项目达标口径或任何放宽依据**。
- **8dp 间距**：**不是官方条文**。官方只有「8vp 网格系统」（布局对齐基线，非间距下限）；8dp 是本项目设计决策（`ux-spec §4.1` / `art-bible §6.5` 自定约束）。**不得对外表述为「鸿蒙规定相邻间距 ≥8vp」**。

### 禁止出现的三句话（收口文档与一切对外口径）

1. **「可访问性 Standard 29 条 AC 全通过」**——29 条中 AC-A10-1/A10-2 为 N/A（N/A ≠ PASS），27 条可判项里还有 fixture 断言（B 档）与真机唯一（C 档），**没有任何口径能拼出「全通过」**。
2. **「性能已达标」**——§10.1 全部数字仍是建议基线，真机校准未执行（EX-03），冻结属 P-7 / 主理人。
3. **「48dp 已重验」**——重验须真机环境针对真实渲染热区矩形；断言库常量正确 ≠ 控件达标 ≠ 真机达标。
