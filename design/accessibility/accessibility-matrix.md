### 0.2 分级：Standard 起步 / Comprehensive 目标

**本作采用「Standard（标准级）起步，Comprehensive（全面级）为目标」**（C-4 已由用户拍板按推荐执行；art-bible §9.1）。

引用 art-bible §9.1 的定级理由（原文要点）：

> 城市建造**高度依赖颜色编码**（分区、状态、通勤），且概念文档视觉锚点 7 明确要求「分区不得只靠颜色区分」；手机小屏 + 密集 UI 使文本缩放与 48dp 热区同为刚需。**Basic 级不足以覆盖本品类风险**；Comprehensive 的完整输入替代与三档色盲调色板可放到 Should 阶段升级。

补充本矩阵的落地解释：

- 分区色（居住 / 商业 / 产业）、状态色（正向 / 警告 / 负向 / 禁用）、通勤流线（畅通 / 缓行 / 拥堵）构成**三套并行的颜色编码**，任一套若只靠色相传达，色觉障碍玩家将无法进行核心决策（划分区、判断预算、诊断拥堵）→ 故色盲友好是**基础要求而非锦上添花**。
- 单屏 ≤3 常驻指标 + ≤1 数据面板 + 底部 1/3 拇指热区的密集 HUD，使文本缩放与热区尺寸直接决定可用性 → 与色盲友好同为 Standard 的必含项。

## 1. 分级定义与本作选择

| 分级 | 一般含义 | 本作取舍 |
|---|---|---|
| Basic | 仅对比度与触控热区 | **不采用**。分区 / 状态 / 流线三套颜色编码并存，缺色盲编码即无法完成核心决策 |
| **Standard（首版）** | 色盲图案编码 + 对比度 + 动效可关 + 文本缩放 + 热区 + 输入替代 + 多通道反馈 + 音频冗余 + 性能可降级 | **采用**。§2 的 29 条 AC 全部为首版 Must |
| **Comprehensive（目标）** | 在 Standard 之上加三档色盲调色板、高对比模式、逐项动效强度、大字号紧凑布局、热区可视化、完整字幕 / 视觉提示强度、自动按帧率降档、更完整输入替代 | **目标**，Should 期升级（§3.2） |
| Exemplary | 全量重映射、完整读屏 / 语音导航等 | 不在本作范围，不承诺 |

> 分级的**提升只允许增加能力，不允许降低 Standard 基线**；Comprehensive 未按期落地时，首版仍须完整交付 29 条 Must AC。

### 2.1 A-01 色盲友好（4 条 AC）

| AC | 可验收判据 | 验收方法 | 责任侧 |
|---|---|---|---|
| AC-A01-1 | **deuteranopia / protanopia / tritanopia 三型模拟 + 灰度**下，3 类 Must 分区（居住 / 商业 / 产业）**100% 可区分** | 导出 3 分区同屏截图，逐型模拟；移除颜色后仅凭圆点阵 / 45° 斜线 / 正交网格 + 图标 + 文字标签仍可辨认；3 套图案层（asset-spec M-056~058）均存在且启用 | 美术 / QA |

| AC-A01-4 | 色板**令牌组隔离**：分区组 6 色与状态组 4 色无重复色值、无「改透明度 / 改明度衍生」关系 | 色板文件 / 配置静态比对：分区组 `#A8BE72 #4C96C9 #C08A62 #7B78C4 #2E9E7B #9B8AD9`，状态组 `#0B7A4B #A85C00 #C0261D #5B7A8C`；交集为空 | 美术 / 架构（工具） |

> **脚注 · 预检色 ≠ 状态结论（口径 4 + 口径 5，主理人 T-134 / T-135 裁定）**：**可用性预检（通道 A，即时 <100ms）** 属 **art-bible §3.4 规则 3 已列明的合法使用面「预览边框」**，**不构成状态色滥用**，与本条 AC 不冲突。预检取色**按动作类型区分**：**落位（place）合法 = `status.positive`（合法绿）/ 非法 = `status.negative`（非法红斜纹）；拆除（demolish）合法 = `status.warning` / 非法 = `status.negative`** —— 拆除属破坏性动作，若与落位同用 `positive`，小比例下会误判「在建还是拆」；§8.3 未规定拆除的合法性配色，属**文档空白**，本区分为其合理填充。**结算结论（通道 B，tick 后）** 才由 `flow.*` 通勤三态与 `status.warning` 等表达「**城市现在怎么样**」；**禁止通道 A 使用 `flow.*` 三态色**，也不得用状态结论色表达「结算后的状态」。两类 `warning` 虽同值，但**使用面与位置分离**（预检 = 画布地块边框 / 结算 = HUD 图标），同屏不混淆。依据：art-bible §3.4 规则 3 / §8.3、ADR-004 §2、ux-spec §3.1 V3。

### 2.2 A-02 对比度（3 条 AC）

| AC | 可验收判据 | 验收方法 | 责任侧 |
|---|---|---|---|
| AC-A02-1 | **正文文字对底 ≥ 4.5:1**（WCAG 2.1 AA） | 对 3 常驻指标、议题卡短句、面板正文、诊断归因链逐项取色计算对比度；最小正文 ≥14sp | 美术 / QA |
| AC-A02-2 | **大字（≥18sp / 14sp Bold）、图标、UI 组件边界 ≥ 3:1**；顶 / 底 HUD 为不透明底；状态色 L40–50 深色前景在浅底达标 | 取样 M-060 顶部条、M-068 底部 Tab、M-070~084 图标；检查 `#1B2430` 主文字、`#2E6BE6` 主色、`#0B7A4B / #A85C00 / #C0261D` 状态色 | 美术 / QA |
| AC-A02-3 | **全时段与全部天气下校验通过**：MVP 晴朗白天必过；Could 期夜景叠色（深蓝 @30%）与阴 / 雨 / 雪叠色启用时，状态色须做明度补偿后仍达标 | 叠色层开启前后各跑一次自动对比度校验；不因叠色降低而失标（art-bible §5.2 / §9.2） | 美术 / 架构（校验工具） |

> **与官方条文对齐（全矩阵唯一可直接宣称对齐的一组）**：本组 **AC-A02-1 / AC-A02-2** 与华为官方《通用应用 UX 体验标准》**标准编号 2.1.4.1 色彩对比度**（标准等级「必须」）**数值完全一致，无需调整** —— 图标或标题文字与背景 **> 3:1**、正文 **> 4.5:1**。来源：`https://developer.huawei.com/consumer/cn/doc/design-guides/ux-guidelines-general-0000001760708152`。
>
> **口径注 · `base.inkWeak` 属非文字令牌（S-12 用户裁定 A，2026-11-07）**
>
> - **`base.inkWeak`（`#9AA5B1`）是「非文字令牌」**：仅用于装饰线 / 非活动标示 / 分割线，**不受 `AC-A02-1`（正文 ≥4.5:1）约束**；**若将来任何文本节点引用它，即视为 `AC-A02-1` 不达标**。
> - 依据：按 WCAG 2.1 相对亮度公式实测，`#9AA5B1` 对 `base.canvas`（`#F4F6F8`）仅 **2.31:1**，**不满足 WCAG SC 1.4.3 文本对比度 4.5:1**。占位与空态文案改走 `base.inkSecondary`（`#5A6675`），三种底上均 **≥4.9:1**（最低为 `base.tile` `#E8ECEF` 上 **4.92:1**）。
> - **本项目不设三级文字色**：`base.inkSecondary` 之上的第三级文字色在 4.5:1 下**数学不可行**（裁定依据中给出 `base.tile` 上净空 ΔL 仅 **0.0168**）。因此文字色阶只有 **主 / 次 两级**，不引入「弱」级文本。
> - **零视觉变更、零 hex 变更**：本次不调整任何色值，只改令牌语义与使用纪律。代码侧由 `semantic-tokens.ts` 增加 `textSafe: false` 标记 + 静态扫描守卫（**另一工作流负责，本文件不代改**）。

> **表述差异（如实标注，不掩盖）**：官方条文用「**>**」表述，本组 AC 用「**≥**」（WCAG 2.1 AA 口径）；**门槛数值相同**，比较符在临界值上的判定细则以 QA 验收时的实测精度为准，本文件不另立规则。**除本组外，§2 其余各组均不得对外宣称「与官方条文数值一致」**——A-05 是「取官方推荐值 48vp、严于官方必须下限 40vp」，A-10 才是官方条文原文，A-01 / A-03 / A-04 / A-06 / A-07 / A-08 / A-09 无对应官方条文。

>
> 1. **48dp 基线来自官方**：华为官方《通用应用 UX 体验标准》**标准编号 2.1.3.3 点击热区**，标准等级「**必须**」，适用设备：手机、折叠屏、平板、电脑、智慧屏、智能穿戴 →「主要交互元素或控件的可点击热区**至少为 48vp×48vp（推荐），不得小于 40vp×40vp（必须）**」；官方测试方法「观察并计算应用界面点击按钮所占大小」，**判定标准「触屏可点击热区尺寸需大于或等于 40vp×40vp」**。本项目取**推荐值 48vp** 作为基线（**严于**官方必须下限 40vp），较 v0.2.1 的 44dp 上调 4dp。首版只承诺手机竖屏。
> 2. **「间距 ≥8dp」不是官方条文**：官方只有「**8vp 网格系统**」（布局对齐基线），**没有**「相邻热区间距 ≥8vp」的硬性条文。**8dp 间距是本项目设计决策**（出处：`design/ux/ux-spec.md` §4.1 热区行、`design/art/art-bible.md` §6.5 热区行；两份文件均为本项目的自定约束，不是官方条文），**不得对外表述为「鸿蒙规定相邻间距 ≥8vp」**。
> 3. **单位口径**：官方条文用 **vp**，本项目代码与文档用 **dp**，二者概念等价（密度无关像素），不构成两套数值、不产生换算。
> 4. **判定强度未变且在收紧**：v0.2.1 为「≥44dp」，v0.3 为「≥48dp」；均为逐元素实测、不通过即阻塞。44 → 48 是**收紧**，不属于放松；v0.2.1 遗留的「推荐值待核对后对齐」悬置语已在 v0.3 删除（核对已完成：官方 2.1.3.3 推荐值 48vp 即可直接采用，无需再等布局侧回话）。

## 3. 与范围分层的关系

### 3.1 Must —— 不得因排期压缩删除

> 对应 art-bible 附录 D 的 **D-6**：色盲图案编码是视觉锚点 7 的硬要求，**排期压缩时不得删除该层，只能降低图案强度**。

| 项 | 不可删理由 | 压缩排期时允许的最小让步 |
|---|---|---|
| **分区图案编码 3 套（M-056~058）+ 图标 / 文字标签** | 锚点 7 硬要求；删掉即 A-01 全失效，核心决策不可进行 | 只能在 **12–18% 不透明度区间取下限**、或降低图案密度；**不得移除图案层、不得取消图标 / 文字标签、不得降到 0** |
| **状态形状编码 6 项（M-079~084）** | A-01-2 / A-01-3、A-07-1 依赖；删掉即状态只靠颜色 | 可合并等价变体（三角并入 !、横杠并入 ✕），但 6 类语义形状必须齐全 |
| **「状态色 vs 分区色不混淆」校验（AC-A01-3）** | 裁定 8 新增验收项，直接对应 v0.2 收敛成果 | 不得跳过；12 组合矩阵可自动化，但不能取消 |
| **对比度基线（A-02 全部）** | WCAG 2.1 AA 底线，且状态色深色前景方案依赖它 | 无让步空间 |
| **「减少动态效果」开关 + 静态替代资产（M-009 / M-025）** | A-03；缺静态替代则关闭动效后信息丢失 | 可延后「逐项强度调节」，不可延后开关与静态替代 |
| **48×48dp 热区 / 8dp 间距 / 点击替代路径（A-05 / A-06）** | 锚点 7 + GDD P4 + 官方 2.1.3.3 推荐值 48vp；手机单手可用性底线 | 无让步空间 |
| **两级反馈的双通道（A-07）** | 架构硬约束（ADR-004 §2 / S-07，art-bible D-3 已关闭）+ 锚点 8；防「点了没反应」 | 无让步空间 |
| **静音可完整进行（A-08）** | 基础可用性 | 无让步空间 |
| **低档位不降级可访问性（A-09）** | 防止性能档位成为绕过可访问性的后门 | 无让步空间 |
| **官方「必须」级基线：滑动控件高度 ≥20% 屏高、最小字号 ≥8vp（A-10）** | 华为官方标准 2.1.3.4 / AppAnalyzer 规则总览，**标准等级「必须」**；缺任一条即意味着对官方必须项存在未命名缺口 | 无让步空间（**S-12 越界新增行**：A-10 属官方必须级 Must，须列入防裁剪清单，否则排期可合法删除官方必须项。**判定状态标注（主理人裁定·三处统一口径）：`AC-A10-1` 不适用（无适用对象）· 条件重开 / `AC-A10-2` 不适用（无对象）· 条件重开** —— **在 Must 表 ≠ 达标，N/A ≠ PASS**，列入本表只表示「不得删除」，不表示「已验证通过」） |

> **范围纪律**：以上任一 Must 若需调整，须回到用户 / 主理人拍板，不得由制作排期单方面裁剪（GDD 5.1 准入纪律「新增 Must 必须等量移除」同理适用于「删除 Must」）。

### 3.3 与 MoSCoW / 垂直切片的关系

- GDD 5.2 明确「切片验收看闭环通不通，不看内容多不多」，且切片外明确「无季节昼夜」。本矩阵的 29 条 AC **全部属于「闭环可用性」而非内容量**，不因垂直切片裁剪而减少。
- Should / Could 资产（asset-spec §1.2 / §1.3）不得用于满足 Must AC；例如不得用 Could 期夜景叠色来「证明」对比度达标，A-02-3 的夜景校验是**前瞻性校验**，不是把夜景拉进 MVP。
- 折叠屏 / 平板为 Should 级平台特性（GDD 6.2 H2）：**其布局若启用，同样须满足本矩阵全部 AC**；首版未启用不影响手机竖屏的 29 条验收。
