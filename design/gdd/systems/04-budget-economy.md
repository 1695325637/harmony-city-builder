## 1. 系统目标与支柱映射

### 1.1 系统目标

把「土地有限、预算有限」变成可感知的取舍：管理收入 `I`、建设支出 `C_b`、维护费 `C_m`、结余 `B` 与周期结算，并通过 **D6 回路**（满意度 → 收入 → 预算 → 投入 → 满意度）让经济与城市质量互相牵动。核心红线是**软着陆**：财政吃紧只告警、不判负、不形成不可逆死亡螺旋（概念 9.1 R5 / OD-1 A）。

### 1.2 支柱映射

| 支柱 | 本系统如何服务 | **本系统不得命中否决列的红线** |
| --- | --- | --- |
| **P2 每笔投入都有机会成本** | 建设有一次性支出、所有建筑 / 道路有持续维护费、结余有限 | ❌ 不得有零成本建造 / 无维护费建筑 / 免费扩张；❌ 不得有「建成即永久收益」 |
| **P1 满意度是唯一计分板** | 结余 `B` 是**过程量**，只作为约束与常驻可读指标，不是终局得分 | ❌ 不得把「财政评分」做成与 `S` 并列的第二终局轴；❌ 不得有结余排行榜 / 攒钱成就 |
| **OD-1 A 无硬终局** | 赤字只触发告警与建设抑制，可回退重试 | ❌ 不得 Game Over / 破产即失败 / 不可恢复的死亡螺旋 |
| **P4 拇指宽的决读优先** | 常驻只显示「预算结余」一个数值；明细进次级面板 | ❌ 不得把收支明细表摊在常驻 HUD |

### 1.3 拍板约束核对（OD 全 A）

- **OD-1 A**：无硬性终局、未达标可回退重试 ✅（本系统提供回退所需的周期初快照契约）。
- **OD-2 A**：周期结算由「结束本日」驱动，不做离线推进、不做后台计时 ✅。
- **OD-4 A**：固定地图 → 维护费随扩张阶梯上升但**有上界** ✅。
- **OD-3 A**：不做个体市民经济（无个体收入 / 个体消费）✅。

## 3. 规则 / 数据结构

### 3.1 账目模型

| 项 | 定义 | 单位 | 出现时机 |
| --- | --- | --- | --- |
| `I_t` 收入 | 由人口与**上一 tick 满意度**驱动 | `CU/周期` | 周期结算 S7 |
| `C_b,t` 建设支出 | 新建分区 / 道路的一次性成本 | `CU` | 建造时（暂停态提交） |
| `C_m,t` 维护费 | 已有建筑 / 道路的持续成本 | `CU/周期` | 周期结算 S7 |
| `I_f` 财政投入 | 玩家拨付的**抽象市政服务支出** | `CU/周期` | 周期初拨付；下一 tick 供 01 的 `f_f` |
| `B_t` 结余 | 可结转、可为负（软着陆） | `CU` | 常驻可读 |

> **`I_f` 的 MVP 抽象化说明**：MVP 只有 R/C/I 三类分区、无公共服务建筑（概念 5.1）。`I_f` 定义为**不占地块的聚合市政服务支出**（道路养护、环卫、公共照明等抽象项），以聚合形式提升 01 的 `f_f`，**不生成任何新建筑或分区**。这样既保留「拨」这个动词与 `f_f` 因子，又不突破切片边界。是否应在 Should 期落地为可见的公共服务设施，见 8.1 O-4（需主理人裁定）。

### 3.2 周期与结算

- 一个「市政周期」由 `K` 个 tick 组成（`1 tick = 1 游戏日`，`K` 为占位，与 01 的 O-4 协同）。
- 结算发生在**本周期最后一个 tick 的 S7**，使用 `S_{t−1}`（单 tick 滞后，systems-index 3.3）。
- 结算内容：`I_t` / `C_m,t` 入账 → 更新 `B_t` → 目标判定（`S ≥ S_unlock`）→ 解锁或允许回退。

### 3.3 软着陆（R5 的核心机制）

| 触发 | 处理 | 明确禁止 |
| --- | --- | --- |
| `B_t < 0` | ① 生成「预算吃紧」议题（交 05）；② 抑制新增建设（`C_b` 需 `B ≥ 0` 或分期）；③ 收入有下限 `I_min` 保证不归零；④ `B` 有下限 `B_floor` 钳制 | ❌ 判负 / Game Over / 强制拆除 / 不可逆螺旋 |
| 连续多周期赤字 | 保持可恢复：玩家可通过 V8 调（降密度、拆冗余道路、调整 `I_f`）逐步回正 | ❌ 债务复利 / 罚息滚雪球 |
| 未达标 | 回到**周期初快照**重试（OD-1 A），结算幂等 | ❌ 重复扣费 / 重复解锁 |

### 3.4 结余消耗口（防「钱多到无约束」的无聊区）

1. 新建 / 改划分区与道路（`C_b`）；
2. 公共服务投入 `I_f`（→ 01 的 `f_f` → `S`，形成 D6 闭环）；
3. 可选的 `B_cap` 上限或超额的边际递减（占位，见 8.1 O-3）。

> 结余**必须至少有一个与满意度挂钩的出口**，否则会与 P1 脱钩、退化为「攒钱游戏」。

## 4. 核心算法 / 公式骨架

> **全部参数为占位符**，只锁定结构、变量单位与取值范围原则。

| 量 | 骨架公式 | 变量与单位 | 取值范围原则 |
| --- | --- | --- | --- |
| 满意度乘数 | `m(S) = clamp( m_min + (m_max − m_min) × S/100 , m_min, m_max )` | `S [分]` ∈ `[0,100]`；`m` 无量纲 | `0 < m_min < m_max`；`m` 对 `S` **单调不减**（D6 正向） |
| 收入 | `I_t = max( P_t × i_unit × m(S_{t−1}) , I_min )` | `P_t [person]`（02）；`i_unit [CU/(person·周期)]`；`I_min [CU/周期]`；`I_t [CU/周期]` | `i_unit > 0`、`I_min > 0`；`P_t = 0` 时由 `I_min` 兜底，**收入不归零**（软着陆）；使用 `S_{t−1}` 解环 |
| 建设支出 | `C_b,t = Σ_zone ( n_zone × c_zone × d ) + n_road × c_road` | `n [cell]`；`c_zone, c_road [CU/cell]`；`d` 密度系数（无量纲，02） | 所有单价 `> 0`；密度越高单价越高（P2）；`B < C_b` 时禁止或分期（E4） |
| 维护费 | `C_m,t = Σ_zone ( n_zone × m_zone × d ) + n_road × m_road` | `m_zone, m_road [CU/(cell·周期)]` | 所有单价 `> 0`；随扩张**阶梯上升但有上界**（固定地图，OD-4 A）；密度越高维护越贵 |
| 结余 | `B_t = clamp( B_{t−1} + I_t − C_b,t − C_m,t , B_floor, B_cap )` | `B [CU]` | `B_floor < 0`（允许赤字）、`B_floor` 有限；`B_cap` 可为 `+∞` 或有限上限（O-3） |
| 财政投入因子 | `f_f = clamp( I_f / I_ref , 0, 1 )`，`I_ref = i_ref × P_t` | `I_f [CU/周期]`；`i_ref [CU/(person·周期)]`；`I_ref [CU/周期]` | 与 01 的 4.1 **逐字一致**；`P_t = 0 → f_f = 0`；`I_f ≥ 0` |
| 周期达标 | `S_{周期末} ≥ S_unlock` | `S_unlock [分]` | 与 01 / 02 的 O-4 **同一取值**（跨 GDD 一致性硬要求） |

**取值范围通则**：所有单价 / 系数 `> 0` 且有限；`I_t ≥ I_min > 0`；`B` 恒为有限数；所有除法走 01 的兜底；**任何情况下不产生负收入、NaN 或指数增长**。

### 4.5 D6 回路的曲线验证思路（不替测试定方法）

要求平衡期对以下三条曲线做参数扫描与目视 / 数值检查，判据为「**不发散、不锁死、不单调到无解**」：

| 曲线 | 横轴 | 纵轴 | 需要排除的形态 |
| --- | --- | --- | --- |
| C-1 收入—满意度 | `S [分]` | `I [CU/周期]` | 斜率过大导致「满意度稍降即崩盘」；或过平导致投入无意义 |
| C-2 维护费—扩张 | 已建格数 `[cell]` | `C_m [CU/周期]` | 阶梯过陡导致 D3 变不可逆死亡螺旋；或过平导致 P2 失效 |
| C-3 结余—周期 | 周期序号 | `B [CU]` | 持续单调下行（锁死）或持续单调上行（无聊区）；应呈可恢复的波动 |

> 三条曲线的联合检查由严守真按 AC-E3 执行；本 GDD 只给出需要排除的形态，不定义测试用例与工具。

## 6. 边界与 Won't

### 6.1 边缘情况（≥3 类，逐类给出处理原则）

| # | 边缘情况 | 处理原则 |
| --- | --- | --- |
| E1 | **`B_t < 0` 且连续多周期** | 走软着陆（3.3）：告警 + 抑制新增建设 + `I_min` 保底 + `B_floor` 钳制；**不判负、不强制拆除**；玩家可逐步回正 |
| E2 | **`P_t = 0` 或 `S_{t−1} = 0` 导致收入趋零** | `I_t = max(…, I_min)` 兜底；不出现负收入、不出现「零收入即锁死」 |
| E3 | **回退后重复结算** | 回退到周期初快照，`B / I_f / 解锁标志` 一并回滚；结算**幂等**，不得重复扣费 / 重复解锁（A-6） |
| E4 | **一次性大规模建设使 `C_b > B`** | 禁止该笔建造并给即时非法反馈，或分期（占位，见 O-2）；不得产生负结余越界、不得静默扣成巨额赤字 |
| E5 | **结余无限累积（无聊区）** | `B_cap` 上限 / 超额边际递减（O-3）；且 `I_f` 提供与 `S` 挂钩的持续消耗口 |
| E6 | **`I_f = 0`（玩家完全不拨服务投入）** | `f_f = 0`，`S` 经 01 的短板惩罚下降并生成议题；不报错、不阻断结算 |
| E7 | **周期末恰逢回退与解锁同帧** | 结算顺序固定：先判定 → 再解锁 / 回退 → 最后写快照；两者互斥，不得同时发生 |

### 6.2 Won't（明确不做）

- ❌ 不做硬终局、破产判负、债务复利、罚息滚雪球（OD-1 A / R5）。
- ❌ 不做与 `S` 并列的财政评分、结余排行榜、攒钱成就（P1）。
- ❌ 不做地价、债券 / 贷款、实时高频经济波动、交易所、付费加速、内购（概念 5.1 / 商业化 Won't）。
- ❌ 不做个体市民经济（收入 / 消费按个体聚合，OD-3 A）。
- ❌ 不做公共服务建筑（MVP 的 `I_f` 为抽象聚合支出，见 3.1）。
- ❌ 不定义存档实现、状态机、结算原子性、性能预算（架构职责，见第 8 节）。
