## 1. 系统目标与支柱映射

### 1.1 系统目标

把 02 的地块与 OD 需求求解成**通勤图**，产出平均通勤时长 `T_c`、生活服务可达时长 `t_g`、通勤图距离 `d(i,g)` 与路段饱和度 `q/cap`，供 01 计算 `f_c / f_s / f_e`。它是 **P3「城市是流动系统」的主要承载者**，也是 D1 通勤潮汐、D2 拥堵负反馈的发生地。

### 1.2 支柱映射

| 支柱 | 本系统如何服务 | **本系统不得命中否决列的红线** |
| --- | --- | --- |
| **P3 城市是流动系统** | 分区价值取决于「连到哪里」：所有时长走通勤图路径，不用直线 / 静态半径 | ❌ 不得用欧氏距离 / 半径内即覆盖；❌ 不得绕过路网的传送式服务 |
| **P4 拇指宽的决读优先** | 通勤流用**线宽 / 亮度**抽象表达，不画逐辆车（锚点 5）；玩家只「连」一类道路 | ❌ 不得逐车个体仿真 / 粒子车流 / 写实车模；❌ 不得要求玩家微调单条车流 |
| **P2 每笔投入都有机会成本** | 道路占用 `ROAD` 地块并产生维护费（由 04 计），容量有限 | ❌ 不得有无限容量道路 / 免费路网 |
| **P1 满意度是唯一计分板** | `T_c` / `q/cap` 是中间量，只经 01 折算进 `S` | ❌ 不得把「通行效率」做成并列终局指标 |

### 1.3 拍板约束核对（OD 全 A）

- **OD-2 A**：默认暂停、一次点按结算一 tick；路网编辑在暂停态即时可见、tick 后重新求解 ✅。
- **OD-4 A**：固定有限网格；通勤图规模有上界，不做无尽路网 ✅。
- **OD-1 A**：拥堵不判负，只通过 `f_c/f_s` 拉低 `S`，可回退重试 ✅。

## 3. 规则 / 数据结构

### 3.1 通勤图

| 项 | 定义 |
| --- | --- |
| 图 | `G = (V, E)`；`V` = 道路格 / 路口节点，`E` = 相邻道路格构成的边（1 类道路，MVP 不分级） |
| 来源 | 仅从 02 的 `Cell.zone = ROAD` 派生；**02 是唯一权威状态**，03 不另存一份地块表 |
| 容量 | 每条边 `cap_e [FU/tick]`（抽象流量单位），单一道路类型 → 同一 `cap` 基值；`cap_e > 0` |
| 需求 OD | 两类：① 上班流 `R_g → I_i`；② 生活服务流 `R_g → C_i`。均由 02 的 `P_g [person]`、`J_i [job]` 生成 |
| 抽象表达 | 通勤流用**线宽 / 亮度**编码流量；拥堵用语义色脉冲；**不画逐辆车**（锚点 5 / 美术圣经 §3.3） |

### 3.2 求解产物（每 tick S2 输出）

```
TrafficResult_t = {
  T_c          : float,        // 平均上班通勤时长 [min]                 → 01 的 f_c
  t_g[]        : float[],      // 各居住格到最近商业格的可达时长 [min] → 01 的 f_s
  d(i,g)       : float,        // 产业格 i 到居住格 g 的通勤图距离 [min] → 01 的 f_e
  q_over_cap[] : float[],      // 各边饱和度（无量纲）                   → 05 的拥堵归因
  flowState_e[]: enum[],       // 各边流线三态 'clear'|'slow'|'congested'（派生视觉量，判定口径见 3.5）→ UX / 渲染
  unreachable  : bool          // 是否存在不可达 OD
}
```

> **不可达约定**：不可达时路径时长取 `T_max [min]`（01 的 `f_c` 兜底阈值），**不得返回 `∞` 或 NaN**；`unreachable = true` 交 05 生成议题。

### 3.3 拥堵负反馈（D2）

```
q/cap ↑  →  t_e ↑  →  ① T_c ↑ → f_c ↓ → S ↓（上班）
                    ② t_g ↑ → a_g ↓ → f_s ↓ → S ↓（服务抵达变慢）
```

- 拥堵**不直接扣分**，只通过 01 的两个因子传导，保证 P1 单一计分板。
- 拥堵也不判负（OD-1 A），玩家可通过 V5 连 / V8 调 回头改路网，形成二次决策。

### 3.4 视觉契约（只读引用，不替美术定稿）

- 流线层独立于分区色层、默认半透；畅通 / 缓行 / 拥堵三态用线宽 + 亮度 + 形状编码，遵守美术圣经 §3.3 与概念锚点 5。
- 具体色值、线宽、动效参数以 `design/art/art-bible.md` 为准；本 GDD 只要求「流量可编码、拥堵可区分、无逐车实体」。

### 3.5 流线三态判定口径（T-130 补充 · S-08 前置）

> **本节补的是「分类权归谁 + 按什么量分类」，不是视觉参数。** §3.4 已把色值 / 线宽 / 动效留给美术圣经 §3.3；本节只定义**用哪个模拟量、用什么阈值键、由哪一层判定**。若留空，渲染 / UI 只能拿 `T_c` 或 `q_over_cap[]` 自己判阈值——这直接违反 ADR-004「UI 零写权威状态、权威值只来自 `Δ_t`」与 `architecture.md` §9.1「渲染与 UI 都只查令牌表」。

#### 3.5.1 分类基准：**路段饱和度 `q_e / cap_e`（逐边）**

| 候选 | 结论 | 理由 |
| --- | --- | --- |
| **(a) 逐边饱和度 `q_e / cap_e`** | **✅ 采纳** | ① 三态是**画在路段上**的（美术圣经 §3.3 三档流线色、§7 线宽细 / 中 / 粗 × 亮度低 / 中 / 高），必须**逐边**可判；② `q_over_cap[]` 已由 §3.2 每 tick 产出，**无需新增原料**；③ 玩家改一条路时三态只在该路段变化，保住 P3「位置比数量重要」与 V2 诊 的「哪条路堵了」诊断价值 |
| (b) 全网平均 `T_c` | **❌ 不采纳** | `T_c` 是 §4 的**全网加权平均**（单一标量），只能整体变色；一条路大堵会被全网平均稀释，玩家无法定位，与 AC-T2「位置敏感性」、V2 诊 的归因目标相悖 |

- 分类在 **§4 钳制后**的 `q_e / cap_e`（即 `[0, (q/cap)_max]` 内）上判定，避免超饱和边溢出分档。
- **三态只描述「流量拥挤程度」，不描述「可达性」**：不可达 OD 仍由 `unreachable` 交 05 生成议题，不改变该边按流量着色（例如边本身 `q = 0` → 显示畅通，同时议题面板提示不可达）。
- `cap_e = 0` 走 §6.1 E3 的除零兜底，`q/cap` 取兜底值 → `clear`，不产生 NaN。

#### 3.5.2 阈值键名与占位（**不含任何具体数值**）

```
flowState_e = 'congested'  if  q_e/cap_e >  <θ_slow>
              'slow'       if  <θ_clear> <  q_e/cap_e ≤ <θ_slow>
              'clear'      if  q_e/cap_e ≤  <θ_clear>
```

| 配置键 | 占位符 | 含义 | 约束 |
| --- | --- | --- | --- |
| `flowClearMaxQOverCap` | `<θ_clear>` | 「畅通 → 缓行」的上界 | `0 < θ_clear < θ_slow` |
| `flowSlowMaxQOverCap` | `<θ_slow>` | 「缓行 → 拥堵」的上界 | `θ_slow ≤ (q/cap)_max`（与 §4 钳制上界一致） |

> **占位口径**：`<θ_clear>` / `<θ_slow>` **一律为占位、不写任何具体数值**——「平衡期定，S-12 前钉定；由配置表注入，不阻塞 S-01 / S-02 / S-08 开工」，与 `v0 / β / γ / cap / (q/cap)_max` **同批钉定**（见 §8.1 O-5）。
> **反向约束（重要）**：这两个阈值**只影响 `flowState_e` 的分档位置，不得进入 `T_c` / `f_c` / `S` 的计算链**。否则视觉阈值会变成隐藏的平衡参数，既破坏 P1 单一计分板，也会让 AC-T1 的单调性断言依赖一个视觉量。**改阈值不得改变任何模拟输出。**

#### 3.5.3 唯一真源与分层职责（ADR-004 双通道）

| 层 | 职责 | 禁止 |
| --- | --- | --- |
| **模拟层（P2）** | 用 §4 钳制后的 `q_e/cap_e` 与 `<θ_clear>/<θ_slow>` 分类，产出 `flowState_e[]`（与 `q_over_cap[]` 同长、逐边对齐）；写入 `TickSnapshot`（A-2 已确认的自包含快照）并随 `Δ_t` 下发 | — |
| **渲染层** | 只做**枚举 → 令牌映射**：`clear → flow.clear`、`slow → flow.slow`、`congested → flow.congested`；令牌按项目 `group.subkey` 点号约定命名，与 `src/render/semantic-tokens.ts` 的 `flow.*` 命名空间（子键 `clear` / `slow` / `congested`）**逐字一致**（默认线宽 / 亮度见 `src/render/draw-list.ts` 的 `DEFAULT_FLOW_LINE`）；按令牌取线宽 / 亮度 / 色值 / 形状，色值仍归美术圣经 §3.3。**并产出图例条目** `{ flowState, encoding, label }`；其中 `encoding` 为**不透明对象，内部结构由渲染层定义、消费方不得依赖**，`label` 取 `畅 / 缓 / 堵`；供 UI 排布 | ❌ 不得读取 `q_e` / `cap_e` 做阈值比较；❌ 不得从 `T_c` 反推三态；❌ 不得在贴图里硬编码近似色 |
| **UI（HUD / 诊断面板）** | 只消费**枚举、语义标签与渲染层下发的图例条目**，负责**排布与文字**（图例位置、议题卡文案、可访问性图例） | ❌ **不引用 `flow.*` 字面 id、不解析 `encoding` 内部**（`src/README.md` 令牌契约：`flow.*` 由渲染层自用、**UI 不依赖**）；❌ 不得自行判阈值、不得重算三态；❌ 不得持有权威状态（ADR-004） |

- **枚举 ≠ 令牌（跨层契约）**：`flowState` 是模拟层产出的**语义枚举**（`clear / slow / congested`），UI 可消费用于图例文字与议题文案；`flow.*` 是渲染层的**视觉令牌**（颜色 / 线宽 / 亮度 / 形状），**只在本层内使用、UI 不引用**（对齐 `src/README.md` 令牌契约的「不依赖」表：通勤态由渲染层自用，改动仍受「先公告」约束）。二者由渲染层内部完成映射、不跨到 UI 层——既让 UI 能画图例，又不让 UI 反向依赖渲染外观。
- **三层边界闭合（T-130 追加 · 主理人裁定）**：**模拟层出枚举 → 渲染层出编码 → UI 排布文字**。图例的三个色块 / 形状由渲染层随图例条目下发（`encoding` 为**不透明对象**，UI 不解析其内部字段），UI 只负责摆位置与写标签。这样 UI 既不必引用 `flow.*` 字面 id、也不用自己画色块，绕开「UI 想画图例 → 就得依赖渲染令牌」的死循环（依据 `architecture.md` §9.1「渲染层与 UI 层都只查这张表」+ `src/README.md`「UI 不依赖 `flow.*`」）。
- **与两级反馈的关系**：§2 表中 V5「铺路 → 路段流线即时更新（<100ms）」指**几何与落位**（通道 A：路径走向、端点、是否连通、选中高亮），用**未分类的中性描边**绘制；**三态着色属通道 B**，只在 tick 结算后由 `flowState_e[]` 驱动。二者不冲突：暂停态铺的新路会立刻出现线条，但其 `clear / slow / congested` 着色要等下一次「结束本日」。
- **可访问性**：三态不得只靠颜色区分，须叠加线宽 + 亮度 + 形状（美术圣经 §3.3 / 可访问性矩阵 A-01「色盲友好」）；「减少动态效果」开启时拥堵脉冲降级为静态箭头 / 描边（见 O-4）。

## 4. 核心算法 / 公式骨架

> **路径分配算法选型不指定**（最短路 / 全有全无 / 迭代分配等由架构与性能预算决定，见 A-4）。本节只锁定**输入输出的量纲、单调性与取值范围**。全部参数为占位。

| 量 | 骨架公式 | 变量与单位 | 取值范围原则 |
| --- | --- | --- | --- |
| 自由流时长 | `t0_e = len_e / v0` | `len_e` 边长 `[cell]`；`v0` 自由流速度 `[cell/min]`；`t0_e [min]` | `v0 > 0`、`len_e > 0`；`t0_e` 有限正数 |
| 路段实际时长 | `t_e = t0_e × ( 1 + β × (q_e/cap_e)^γ )` | `q_e` 路段流量 `[FU/tick]`；`cap_e [FU/tick]`；`β` 无量纲；`γ` 无量纲；`t_e [min]` | `β > 0`、`γ ≥ 1`；`q_e/cap_e` 先钳制到 `[0, (q/cap)_max]`；**`t_e` 对 `q/cap` 单调不减** |
| 路径时长 | `path_time_od = Σ_{e∈path} t_e` | `[min]` | 不可达 → `T_max`；多路径等长时取确定性选择（见 E3） |
| 平均通勤时长 | `T_c = Σ_od ( q_od × path_time_od ) / Σ_od q_od` | `q_od [person/tick]`；`T_c [min]` | `Σ q_od = 0` → `T_c = 0`（空城，不除零）；`T_c ≤ T_max` |
| 生活服务可达 | `t_g = min_{i∈C} path_time(R_g → C_i)` | `[min]` | 无商业格 / 不可达 → `t_g = T_s,max`（01 的 `f_s` 阈值） |
| 通勤图距离 | `d(i,g) = path_time(I_i → R_g)` | `[min]` | 供 01 的 `f_e` 分母 `1 + d(i,g)`；不可达 → `T_max` |
| 饱和度 | `q_e/cap_e` | 无量纲 | `cap_e > 0`；输出前钳制，防溢出 |

**取值范围通则**：所有时长 `≥ 0` 且有限；所有分母 `> 0` 或走兜底；拥堵系数使 `t_e ≥ t0_e`；**任何情况下不产生 `∞` / NaN**。

## 6. 边界与 Won't

### 6.1 边缘情况（≥3 类，逐类给出处理原则）

| # | 边缘情况 | 处理原则 |
| --- | --- | --- |
| E1 | **路网不连通 / OD 不可达** | `path_time = T_max`、`t_g = T_s,max`、`unreachable = true`；`T_c` 仍可计算（用 `T_max` 加权）；不除零、不崩溃，交 05 生成议题 |
| E2 | **`q_e/cap_e` 超饱和（>1）** | 先钳制到 `(q/cap)_max` 再代入拥堵公式；`t_e` 有限；不产生指数爆炸 |
| E3 | **多路径等长 / 环路 / 零长度环** | 采用**确定性**的平局打破规则（如节点坐标字典序），保证同输入同输出（01 的 AC-F4 快照可回放）；禁止环路导致无限累加 |
| E4 | **暂停态连续改路网后一次推进** | 编辑合并为单一 `input_version`；S2 只求解一次；流线即时反馈与模拟结果分离 |
| E5 | **空路网 / 无 OD 需求（`Σ q_od = 0`）** | `T_c = 0`、所有 `t_g = T_s,max`、`d = T_max`；不除零；不生成拥堵议题 |
| E6 | **单格孤立道路（端点无接入）** | 视为 `V` 存在但无有效 OD 边；不报错，按不可达兜底 |
| E7 | **产业 / 商业格为空** | `t_g` / `d(i,g)` 走阈值兜底；01 的 `f_s` / `f_e` 相应退化，不阻断结算 |

### 6.2 Won't（明确不做）

- ❌ 不做逐车个体仿真、实时车流粒子、写实车模（锚点 5 / 概念 5.1 Won't）。
- ❌ 不做多道路等级（干道 / 支路 / 快速路）、公共交通、桥隧、出行方式分层（Should / 切片外）。

- ❌ **不指定路径分配算法、图存储结构、求解频率、性能预算**（架构职责，见第 8 节）。
