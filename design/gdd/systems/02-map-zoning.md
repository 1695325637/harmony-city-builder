## 1. 系统目标与支柱映射

### 1.1 系统目标

提供**固定有限的网格**与**分区 / 密度**这两个最基础的玩家决策面，并产出其余四个系统所需的原始量：人口 `P_t`、岗位 `J_t`、OD 通勤需求 `q_od`、产业 / 商业格坐标、建筑与道路的计量基数。同时承载 **OD-4 A 的里程碑解锁新区**。

### 1.2 支柱映射

| 支柱 | 本系统如何服务 | **本系统不得命中否决列的红线** |
| --- | --- | --- |
| **P2 每笔投入都有机会成本** | 地块是**有限且不可再生**的资源；新区只能靠达标解锁 | ❌ 不得有免费扩张 / 无限地图 / 不占土地的建造；❌ 不得有零维护地标（维护费由 04 计） |
| **P4 拇指宽的决读优先** | 玩家「划」的是一个区域而非逐栋摆楼；一次点按完成 | ❌ 不得逐栋自由摆楼、不得建筑级微操；❌ 不得把人口做成常驻 HUD 主指标（人口是**过程量**，见概念 P1） |
| **P1 满意度是唯一计分板** | `P_t` / `J_t` 只是中间量，全部折算进 `S` | ❌ 不得给人口规模 / 建成面积独立奖励或里程碑 |
| **P3 城市是流动系统** | 分区的「价值」不由本系统判定，交给 03 的通勤图 | ❌ 不得在分区层做「半径内即覆盖」的静态加成 |

### 1.3 拍板约束核对（OD 全 A）

- **OD-4 A**：固定有限地图 + 里程碑解锁新区 ✅（不做无尽生成、不做多独立场景）。
- **OD-1 A**：未达标可回退重试、无硬终局 ✅（解锁只是推进，失败不判负）。
- **OD-2 A**：暂停态编辑即时可见、tick 后模拟生效 ✅。
- **OD-3 A**：本系统只产出聚合量，不做个体市民 ✅。

## 2. 玩家动词与输入输出

| 动词 | 玩家输入 | 系统输出 | 反馈级别 | 对应规则 |
| --- | --- | --- | --- | --- |

## 3. 规则 / 数据结构

### 3.1 网格

| 项 | 定义 |
| --- | --- |
| 形状 | `N × N` 正方形正交网格，固定有限（OD-4 A） |
| 边长 `N` | **实现基线 `N = 32`（32×32 = 1024 格）为 MVP 硬上限**；**起始解锁子集 `16×16 = 256` 格**，按里程碑解锁至 32×32。平衡期可在 **≤32** 内调整，由配置表注入（S-12 前钉定，不阻塞 S-01 / S-02 开工）。基线来自 `docs/architecture/architecture.md` §10.2 / §11.6 A-3（**已确认**）；**>32×32 须重做通勤求解基准 + 快照体积评估** |
| 坐标 | `(x, y)` 整数，`0 ≤ x,y < N`，单位 `cell`；与美术圣经 §2.1 的 2:1 dimetric 128×64 格一一对应 |
| 初始状态 | 全部 `zone = EMPTY`；`unlocked = true` 仅限**起始 `16×16` 解锁子集**，其余区域 `unlocked = false`（锁定） |
| 解锁 | 周期末 `S ≥ S_unlock` 时解锁下一块预定义新区；新区坐标范围固定写死，不动态生成；解锁区数量与切分形状属平衡期数值（见 8.1 O-2） |

### 3.2 分区与密度

| 枚举 | 名称 | MVP 是否可用 | 产出 |
| --- | --- | --- | --- |
| `R` | 居住 Residential | ✅ Must | 人口 `P_g`、上班 / 生活服务 OD 起点 |
| `C` | 商业 Commercial | ✅ Must | 岗位 `J_i`、生活服务 OD 终点（供 01 的 `f_s`） |
| `I` | 产业 Industrial | ✅ Must | 岗位 `J_i`、上班 OD 终点、环境负荷源（供 01 的 `f_e`） |
| `ROAD` | 道路 | ✅ Must | 通勤图边（拓扑归 03，见 3.4） |
| `EMPTY` | 空地 | ✅ Must | 无产出，占用土地 = 机会成本 |
| 公共服务 / 混合用地 / 公园 / 办公 | — | ❌ **Should / Won't** | 不在 MVP（概念 5.1） |

- **密度 3 档**：`D1 / D2 / D3`，对 `R / C / I` 均适用；建筑外观按「分区 + 密度」自动生长，玩家**不逐栋摆楼**。
- 密度档影响：人口 / 岗位系数、维护费基数（04）、环境负荷权重（01 的 `E`）、视觉体量（美术圣经 §4.2 三档剪影）。

### 3.3 地块数据结构

```
Cell = {
  coord        : (int x, int y),          // 单位 cell
  zone         : enum {EMPTY, R, C, I, ROAD},
  density      : enum {NONE, D1, D2, D3},
  unlocked     : bool,
  region_id    : int,                     // 所属区域（起始区 / 解锁区 1..k）
  input_version: int                      // 最后一次编辑版本，供 01 的 S0 合并
}
```

> `Cell` 是**唯一权威地块状态**；03 的通勤图、04 的计量、05 的分区错配判定均从它派生，不另建平行状态（避免跨文档矛盾）。

### 3.4 与道路的关系

- 道路占用 `ROAD` 地块，同样消耗土地（P2）。
- 02 只负责「标记哪些格是道路」；**通勤图的节点 / 边、容量、路径求解全部归 03**，本文档不定义图结构。
- 冲突优先级：`ROAD` 与 `R/C/I` 互斥；后一次编辑覆盖前一次，并记 `input_version`。

### 3.5 里程碑解锁

```
若 (本周期末 S ≥ S_unlock) 且 (存在未解锁 region_id)
  → 将该 region 内所有 Cell.unlocked 置 true
  → 触发 V9 兑（一次性反馈 + 新的规划目标）
否则
  → 不判负、不锁死（OD-1 A）；可回退重试，下一周期重新判定
```

- `S_unlock [分]` 为占位参数，与 01 的 O-4 协同，平衡期定。
- 解锁**不扩大 `N`**（网格总边界恒定），只是把已存在的锁定格变为可用 → 保证 OD-4 A「固定有限地图」。

## 4. 核心算法 / 公式骨架

> **全部系数为占位符**，只锁定结构、变量单位与取值范围原则。

| 量 | 骨架公式 | 变量与单位 | 取值范围原则 |
| --- | --- | --- | --- |
| 人口 | `P_t = Σ_{g∈R} ( p_unit × d_g )` | `p_unit` 单位密度人口 `[person/cell]`；`d_g` 密度系数（无量纲）；`P_t` `[person]` | `p_unit > 0`；`d(D1) < d(D2) < d(D3)` 且**增幅递减**（如 1 / 1.8 / 2.4 为占位），防「全图拉满 D3」成为主导策略（R2） |
| 岗位 | `J_t = Σ_{i∈C} ( j_C × d_i ) + Σ_{i∈I} ( j_I × d_i )` | `j_C, j_I` 单位密度岗位 `[job/cell]`；`J_t` `[job]` | `j_C > 0, j_I > 0, j_I ≥ j_C`（产业更偏岗位）；同为密度边际递减 |
| 劳动人口 | `P_worker,t = P_t × r_labor` | `r_labor` 劳动参与率，无量纲 | `r_labor ∈ (0,1)`，建议 `[0.4,0.7]` 占位 |
| 岗位平衡比 | `ρ_t = P_worker,t / max(J_t, ε)` | `ρ_t` 无量纲；`ε` 极小正数（`job`）防除零 | `ρ ≈ 1` 为供需平衡；`ρ ≫ 1` 岗位不足、`ρ ≪ 1` 劳力不足，两向都应生成通勤压力 / 议题，不设「唯一最优 ρ」 |
| OD 需求 | `q_od(R_g → I_i) ∝ (P_g × J_i) / Σ J` | `q_od` `[person/tick]` | 归一化使 `Σ q_od = P_worker,t`；具体分配（含 `R→C` 生活服务流）由 03 定义，02 只产出源量 |
| 环境负荷源 | `E` 由 01 按「产业格 + 通勤图距离」计算 | `J_i [job]`、`P_g [person]`、`d(i,g) [min]` | 02 只提供产业格坐标与 `J_i`，**不自行判定负荷**（避免与 01 重复定义） |
| 建设计量 | `A_zoned = Σ (分区格数 × 密度系数)` | `[cell·系数]`，无量纲化计量 | 供 04 计算 `C_b / C_m`；02 不定义金额 |

**取值范围通则**：所有系数 `> 0` 且有限；所有求和在空集时返回 `0`（不产生 NaN）；密度系数单调递增但增幅递减；`ρ` 用 `max(J, ε)` 兜底；任何量不得为负。

## 6. 边界与 Won't

### 6.1 边缘情况（≥3 类，逐类给出处理原则）

| # | 边缘情况 | 处理原则 |
| --- | --- | --- |
| E1 | **全图单一分区**（全 R / 全 I / 全 C） | `J_t = 0` 或 `P_t = 0` 时 `ρ` 走 `max(J, ε)` 兜底；OD 需求为空 → 03 返回 `T_c = T_max`；不除零、不崩溃，并由 05 生成「分区错配」议题 |
| E2 | **改划已有建筑的分区 / 调密度** | 视觉即时更新（<100ms），但 `P_t / J_t / A_zoned` 在**下一次 tick S1** 才重算；不得当 tick 生效（P3 / OD-2 A） |
| E3 | **在 `unlocked = false` 区域操作** | 拒绝编辑 + 即时非法反馈（形状编码，美术圣经 §3.4）；不改变 `Cell`，不消耗预算（04 不扣费） |
| E4 | **`ROAD` 与 `R/C/I` 格重叠** | 后一次编辑覆盖前一次，记 `input_version`；若覆盖导致路网断开，由 03 的不可达处理兜底，02 不自行修复 |
| E5 | **解锁新区时的快照兼容** | 新增格以 `unlocked = true, zone = EMPTY` 写入；`Snapshot` 中未涉及新格的历史帧保持可读，不重算历史 `S`（A-2 / A-6） |
| E6 | **`P_t = 0` 且 `J_t = 0`（空城 / 全拆）** | `ρ` 定义为 0（不除零）；`f_f` 由 01 按 `I_ref = 0 → f_f = 0` 兜底；不判负、可继续规划 |
| E7 | **连续多周期未达标** | 不锁死、不减少已解锁区域；可回退重试（OD-1 A），下一周期重新判定 |

### 6.2 Won't（明确不做）

- ❌ 不做无尽生成地图、超大无缝地图、多个独立城市场景（OD-4 A / 概念 5.1）。
- ❌ 不做公共服务分区、混合用地、街区主题、地价、政策卡片（Should / 切片外）。
- ❌ 不做逐栋自由摆楼、建筑级微操、自由旋转镜头（P4 / 美术圣经 §2.1）。
- ❌ 不把人口 / 建成面积做成常驻主指标或独立奖励（P1）。
- ❌ 不在分区层做静态半径加成（P3）。
- ❌ 不定义通勤图结构、路径算法、网格的最终 `N`、存档实现（03 与架构职责）。
