## 1. 视觉主张

### 一句话

> **一座看得懂、会呼吸的现代微缩都市** —— 用清晰的规划蓝图语言承载高密度经营信息，用克制的暖光与轻盈动效让城市有生活温度。

### 三条风格原则

| # | 原则 | 落地判据 |
|---|---|---|
| P1 | **秩序优先（Readability First）** | 网格、分区、通勤流线、选中态的可读性永远高于装饰细节。任何笔触、粒子或光效若干扰信息判读，一律删除。评审时先做「缩到 50% / 灰度 / 色盲模拟」三看，看不清即不通过。对应 GDD 支柱 P4 与锚点 4。 |
| P2 | **明快克制（Optimistic Restraint）** | 高明度、中低饱和、清冷偏暖中性底色，营造「晴朗工作日里正在被规划的城市」。同屏高饱和色不超过 2 处，且必须承载状态语义；环境动效服务于可读性而非氛围沉浸（锚点 6）。 |
| P3 | **信息即美术（Data as Ornament）** | 预算、满意度、通勤流量、密度等经营数据本身就是视觉语言（分区色带、流线、状态环、热力层），不额外叠一层装饰皮。编码优先级 **图标 > 数字 > 文字**（锚点 4）。 |

### 不做什么（Negative List · 与原则同等效力）

- 不做写实贴图 / PBR 材质 / 法线贴图 —— 风格与移动端性能双重不匹配（锚点 3）。
- 不做赛博朋克霓虹、夜景主基调、童话高饱和、末世暖棕、废土或复古未来（锚点 2 / 6）。
- 不做 Q 版大头比例、拟人化建筑、夸张卡通变形 —— 破坏网格可信度与治理者视角。
- 不做自由旋转镜头、连续自由缩放、多朝向资产集（锚点 1；仅三个固定档位，见 §2.2）。
- 不做屏幕空间重后处理（Bloom 泛滥、景深、动态模糊、SSR、SSAO）。
- 不做逐车个体仿真、实时车流粒子、写实车模、任何车辆 / 市民个体资产（锚点 5；GDD 5.1 Won't、9.3 已知取舍）。
- 不做多面板并排、悬浮窗、PC 式快捷键与密集数值表格作为主交互面（GDD P4 否决项、5.1 Won't）。
- 不做「为好看随意放大单体」—— 建筑与植被共用同一比例尺。

**风格参照（仅取气质，不临摹）**：《Mini Metro》的信息图形克制感与形状编码、现代主义建筑模型的功能几何感、市政规划图的分区可读性；明确排除厚重拟真、无网格自由堆叠与史诗化城市宣传画。

## 2. 视角与构图

### 2.1 投影与角度

- 采用 **2:1 dimetric 等距投影**（水平夹角约 26.57°、等效俯角约 26.6°），**全项目锁死单一角度、正交投影、不提供旋转、不做多朝向资产集**。
  - 理由：Cocos Creator 3.x 的 2D 管线对等距 tile 支持最成熟；2:1 比例像素对齐最干净，正交网格道路绘制与自动合批最友好；资产只需一套朝向。
  - **C-2 已由用户拍板采纳此方案**（裁定 6）。概念锚点 1 中「俯角 30°–45°」的措辞由主理人通知 design-strategist 回改放宽，**美术侧不改动本参数**。
- **不做连续自由缩放**，仅提供 §2.2 的三个固定档位（锚点 1 / 裁定 7）。
- 基础逻辑格：**128 × 64 px @1x**（宽:高 = 2:1）。所有资产尺寸按此格整数倍推导，禁止出现半格尺寸。网格整体规模以 GDD 5.1 建议（24×24 ~ 32×32）为准，美术侧不定义地图尺寸。
- **网格线双态**：规划 / 决策态显性显示，观赏态淡出；两态有明确视觉切换（§6.1）。
- 建筑占格：1×1 / 2×2 / 3×3 三档；建筑高度按占格与密度档成正比，不与屏幕缩放挂钩；单栋建筑在手机屏上的最小可辨识尺寸 **不小于 1 个网格单元**（锚点 3）。
- 等距遮挡：统一按 **Y 轴（屏幕纵向）深度排序**，建筑与植被共用同一排序规则；禁止逐对象手写 `zIndex` 例外。

### 2.2 镜头层级与缩放

| 层级 | 名称 | 建议缩放 | 玩家用途 |
|---|---|---|---|
| L0 | 城市 / 区域级 | 0.5× | 看分区肌理、路网骨架、满意度热力、通勤主干流 |
| L1 | 街区级（**默认操作层**） | 1.0× | 划分区 / 铺路 / 选中地块，规划反馈发生层 |
| L2 | 地块级 | 2.0× | 看单栋建筑、地标、细节动效 |

> **禁止性说明（裁定 7）**：**锁死单一等距角度、不提供旋转、不做连续自由缩放，仅允许 0.5× / 1.0× / 2.0× 三个固定档位切换**（双击回 L1）。不做双指连续缩放、不做角度插值、不做多朝向资产集。概念锚点 1「不做自由缩放镜头」由主理人通知概念侧放宽为「不做自由旋转与连续自由缩放，允许固定档位」。

- 档位切换过程相机缓动 ≤ 200ms，**减少动态效果开启时改为瞬时切换**（§9.2）。此约束直接对应锚点 1「控制资产量、保证手机可读性」。
- 相机边界：不允许拖出城市可建区外缘 + 1 格留白；折叠屏展开态上半屏按同一逻辑，仅可视高度变化。

### 2.3 LOD 表现（层级联动，禁止突变）

| 层级 | 显示 | 隐藏 / 降级 | 粒子 | DrawCall 目标 |
|---|---|---|---|---|
| L0 | 建筑**色块体量 + 分区色 + 图案编码**、路网骨架、通勤流量线、热力层 | 窗格、招牌、植被单株、投影、AO | **全部关闭** | ≤ 30 |
| L1 | 完整建筑剪影、简化窗格、道路标线、成组植被、烘焙投影 | 招牌文字、接触 AO | 仅规划 / 告警类低频发射器 | ≤ 60–80 |
| L2 | 窗格 / 招牌 / 路灯、植被单株、软阴影、接触 AO | — | 按预算开放 | ≤ 120 |

- LOD 切换采用 **尺寸阈值 + 100–150ms 淡入淡出**，不做硬切；同一建筑的三档体量共用同一套轮廓特征（§4.2），保证缩远后仍可辨认分区。
- 所有 LOD 资产打入**同一图集**（§9.3），避免切换时跨图集导致批次抖动。
- **不存在逐车 / 逐市民资产，故无对应 LOD 项**（裁定 5）；通勤流量一律由线宽 / 亮度编码（§3.3、§4.4）。

### 2.4 构图

- 主视觉重心 = 城市可建区；HUD 采用「顶部只读条 + 底部拇指区 + 单面板浮层」，中央画布保持最大连续可见面积，**UI 常驻覆盖率 ≤ 30%**（手机竖屏）。
- 高频操作（分区选择、铺路、拆除、「结束本日」）全部落在 **底部 1/3 拇指热区**（锚点 7）。
- 选中地块 / 规划预览周围强制保留 ≥ 1 格视觉留白，禁止被常驻面板压住；必要时面板自动避让或半透。
- 顶部状态条与底部工具条使用**不透明底**，避免城市画面透出造成文字对比度失控（§9.2）。
- 全项目只有两种画面态，切换须明确可感（§6.1）：**观赏态**（城市本体 + ≤3 指标，网格线淡出，无数据叠层）/ **决策态**（网格线显性 + 分区色块 + 通勤流量线 + 热力 / 诊断层）。

### 3.2 分区色（Zone Colors）· 颜色 + 图案双编码

> **关键约束**：分区是本作最核心的颜色编码。为满足色盲友好（锚点 7、§9.2），**任何分区不得仅靠色相区分**，必须叠加图案编码 + 图标 / 文字标签。色相方向采用锚点 2 建议；所有分区色统一压在**低饱和、中高明度带（L ≈ 70–80）**。

**MVP 只有 3 类分区**（概念 R2 / 5.1），命名与色值统一如下：

| 分区 | 档位 | 色值（锚点色相方向） | 图案编码（叠层） | 说明 |
|---|---|---|---|---|
| 居住 Residential | **Must** | `#A8BE72` 暖琥珀绿 | 均匀圆点阵 | 偏暖、偏亮、点阵 |
| 商业 Commercial | **Must** | `#4C96C9` 青蓝 | 45° 细斜线 | 与主色同族但更灰，避免误认为"可选中" |
| 产业 Industrial | **Must** | `#C08A62` 橙灰 | 正交网格线 | 低饱和橙灰，与状态告警色拉开明度 / 饱和度 |

**可选变体（非 MVP，不得进入 Must 资产清单）**：

| 分区 | 档位 | 色值 | 图案编码 | 说明 |
|---|---|---|---|---|
| 公共服务 Civic | Should | `#7B78C4` 靛紫 | 十字 / 加号 | 消防、学校、医院、市政设施（GDD 5.1） |
| 公园 / 绿地 | Could | `#2E9E7B` 青绿 | 树冠形散点 | **居住 / 商业 / 产业的分区变体**，非独立核心分区 |
| 办公 / 商务 | Could | `#9B8AD9` 紫 | 竖向细条 | **商业的高密度变体**，非独立核心分区 |

- 图案层作为**独立半透明贴图**（建议不透明度 12–18%）叠加在地块 / 建筑顶面，统一打入 `UI-图案编码` 图集；"高对比模式"下提升不透明度至 30% 并加 1px 深色描边。
- **MVP 只需 3 套图案**（3 个 Must 分区）+ 1 套公共服务备用。§4.2 建筑表、§6.2 底部 Tab、附录 A 资产与图案清单均已按此收敛；**公共服务 / 公园 / 办公的建筑与图案资产一律标 Should / Could，不得出现在 Must**。
- 分区色只用于**地块填充 / 建筑顶面 / 分区图标**，不得挪作状态提示（锚点 2）。
- **文字承载例外（v0.2.1 增补，依据 T-120 评审 A-10 + 用户授权）**：当画布元素已由**文字标签**直接承载语义时（例如地块上标注「居住」、提示条写明「预算不足」），该元素可**豁免图案编码** —— 文字本身构成第二个可辨通道，仍满足「不得仅靠色相区分」。但此例外**不适用于无文字承载的色块**：纯色分区填充仍须保留图案编码（圆点 / 斜线 / 正交网格），纯色状态圆点或徽标仍须保留形状编码（✓ / ! / ✕ / 锁 / ↑↓）。本例外**不修改** §3.4「四重隔离」与 §9.2 的基线要求。
- **注**：状态编码本就不使用图案（只用形状，见 §3.4 规则 4），故本例外实际作用于**分区图案层**；状态侧「色 + 形状」双编码要求不变。

### 3.3 通勤流量色（独立叠加层，锚点 5）

| 状态 | 色值 | 表现 |
|---|---|---|
| 畅通 | `#5B7A8C` 低饱和深灰蓝（中性无告警） | 细线 + 低亮度 |
| 缓行 | `#A85C00` 深琥珀 | 线宽加粗 + 亮度提升 |
| 拥堵 | `#C0261D` 深红 | 最粗线宽 + 最高亮度 + 路口语义色脉冲 |

- **流量由「线宽 / 亮度」编码，不画逐辆车**；路径抽象但可读，明确反对粒子车流与写实车模（锚点 5）。
- 流线色同样遵循 §3.4 的**状态语义色纪律**：高饱和、低明度（L ≈ 40–50），与低饱和中明度的分区色（L ≈ 70–80）拉开距离，且**不复用任何分区色值**；畅通档刻意采用中性灰蓝，避免与分区绿族产生联想。
- 流线绘制在**独立 RenderLayer / 叠加层**，与分区色做视觉隔离；默认半透 60–75%，避免盖住建筑与分区图案。
- 方向信息由沿线亮度梯度承载；"减少动态效果"开启时改为静态箭头 + 形状标注（§9.2），不依赖运动。
- 拥堵脉冲为语义色 + 形状（! / 横杠）双通道，不单独依赖颜色。

### 3.4 状态色与正负语义（重要 · 裁定 8 已收敛）

> **设计前提**：锚点 2 要求「满意度 / 告警另用独立语义色，不得占用分区色相」。分区色已占满黄绿 / 青蓝 / 橙灰 / 靛紫等色相方向，因此本作改用**明度带 + 饱和度带 + 使用面 + 形状**四重隔离，而非单纯换色相：分区色为「低饱和 / L 70–80」，状态色为「高饱和 / L 40–50」，在浅色底上同时获得更好的前景对比度。

| 状态 | 色值（v0.2 修订） | 明度带 | 形状编码（强制） | 用途 |
|---|---|---|---|---|
| 正向 / 满足 / 可用 / 增长 | `#0B7A4B` 深翠绿 | L ≈ 45 | ✓ / 向上箭头 | 预算结余、满意度回升、规划合法预览 |
| 提示 / 警告 | `#A85C00` 深琥珀 | L ≈ 42 | ! / 三角 | 预算吃紧、满意度下滑、容量将满 |
| 负向 / 拥堵 / 亏损 / 不满 | `#C0261D` 深红 | L ≈ 42 | ✕ / 向下箭头 / 横杠 | 赤字、议题告警、规划非法预览、道路拥堵 |
| 禁用 / 未解锁 | `#B8C0C8` 灰（中性，不占任何色相） | L ≈ 76 | 锁形 | 降饱和 + 60% 不透明度 |
| 选中 / 焦点 | 主色 `#2E6BE6` | — | 2px 描边 + 淡光晕 | 与状态色不冲突，最高优先级 |

**四重隔离规则（硬约束）**：

1. **色值不复用**：状态色**不得复用任何分区色值**（§3.2 六色），也不得由分区色改透明度 / 改明度衍生；色板中分区色与状态色分属两个独立令牌组，由色板文件强制隔离。
2. **明度 / 饱和度带隔离**：分区色低饱和 L 70–80（用于**填充**）；状态色高饱和 L 40–50（用于**前景**）。两者同屏时背景 / 前景关系明确，不会互相"跳"。
3. **使用面隔离**：状态色仅用于 HUD 图标、数值、描边、告警脉冲与预览边框，**绝不用于地块或建筑填充**（填充权只属于 §3.2 分区色）。
4. **形状编码隔离**：任一状态至少两个通道（色 + 形状）；**状态形状只能取 ✓ / ! / ✕ / 锁 / ↑ / ↓ / 三角 / 横杠，禁止使用分区图案**（圆点阵 / 斜线 / 正交网格 / 十字 / 树冠散点 / 竖条），避免去色后两类编码混淆。任一状态变化不得只靠颜色（§9.2）。

> 与 v0.1 的差异：原正向 `#2FA36B`、警告 `#E9A23B`、负向 `#E05A4F` 与住宅黄绿 / 公园青绿 / 产业琥珀棕色相偏近，已按裁定 8 全部替换为深色高饱和版本；§3.3 流线色同步替换。§9.2 色盲模拟验收已增加「状态色 vs 分区色不混淆」一条。

> **关于「红涨绿跌」**：本作是**城市经营模拟，不是金融 / 行情产品**。数值正负向一律采用**通用 UI 语义**（绿 = 正向 / 增长 / 满足，红 = 负向 / 亏损 / 告警），以保证跨品类用户直觉一致。中国区「红涨绿跌」仅适用于证券 / 金融行情语义，**不适用于本作**（GDD 5.1 Won't 亦明确排除「交易所 / 高频经济波动」）；若后续版本加入证券、交易或任何金融玩法模块，须为该模块单独做本地化配色适配，不得改动全局状态色。见附录 C 附带确认项与附录 D-7。

### 3.5 配色纪律

- 遵循 **60 / 30 / 10**：中性底（画布 + 面板 + 地块）≈ 60%，主色 + 分区色 ≈ 30%，状态 / 强调色 ≈ 10%。
- 同屏高饱和强调色 ≤ 2 处；任一分区色不得用于非该分区的语义；**任一状态色不得复用分区色值**（§3.4 规则 1）。
- 全项目色值集中在**一张配色表 / 一个色板文件**中维护，按「基底 / 分区 / 状态 / 流线」分组，**分区组与状态组不得互相引用**；资产与 UI 只引用色板令牌，禁止在贴图里硬编码近似色。
- 对比度硬线：正文文字对底 **≥ 4.5:1**，大字（≥ 18sp / 14sp Bold）与 UI 组件边界、图标 **≥ 3:1**（WCAG 2.1 AA），见 §9.2。
- 基底保持「低饱和清冷」，明确排除赛博霓虹、童话高饱和、末世暖棕（锚点 2）。

## 4. 造型语言

### 4.1 几何总则

- **基础语汇**：直角立方体 + 简洁退台 + 少量坡顶；统一圆角半径（建议 2px @1x，或按格宽 1/64 取整）；禁止复杂曲面、雕花、不规则轮廓。
- **现代主义 / 功能主义**：模块化楼层、干净块面、矢量感或低多边形，**不做写实贴图**（锚点 3）。
- **三面明度阶梯**：所有立体体块按固定光源（左上 45°）烘焙为 顶面 100% / 亮侧 85% / 暗侧 70%（§5.1），造型阶段即按此三分面切块，不依赖运行时光照。
- **轮廓优先**：任何资产先通过"纯黑剪影可辨性"检查，再上色。L0 远景只看剪影 + 分区色（§2.3）；**密度 3 档必须在轮廓高度与体量上一眼可辨**（锚点 3）。
- **比例尺统一**：1 格 ≈ 3–4 m 逻辑尺度；植被 ≈ 0.8 格高；禁止为视觉突出放大单体。单栋建筑最小可辨识尺寸 ≥ 1 格（锚点 3）。

### 4.2 建筑体块与时代感（当代 2020s）

| 类别 | 档位 | 密度档 | 轮廓特征（剪影识别点） | 色彩倾向 |
|---|---|---|---|---|
| 居住 | **Must** | 低 | 2–3 层坡顶 / 双坡小体量、离散排布 | 米白 + 砖红 / 木色点缀 |
| 居住 | **Must** | 中 | 板式小高层、平顶、重复窗格阵列、阳台横带 | 浅灰 + 暖灰 |
| 居住 | **Must** | 高 | 塔式高层、顶部退台、竖向线条、成组出现 | 冷灰 + 玻璃蓝 |
| 商业 | **Must** | 低 / 中 / 高 | 大底盘 + 横向条窗 + 招牌带（高密档加裙房与顶部标识） | 灰蓝 + 辅色橙点缀 |
| 产业 | **Must** | 低 / 中 / 高 | 低矮大跨度、锯齿屋顶、圆柱储罐 / 方形烟囱几何化 | 灰褐 + 低饱和橙灰 |
| 公共服务 | Should | 单层 | 对称立面、门廊 / 钟塔 / 十字标识等符号化构件 | 靛紫 + 白 |
| 公园（分区变体） | Could | — | 非建筑：几何树冠团簇 + 铺装小径 + 水景色块 | 青绿 + 暖灰铺装 |
| 办公 / CBD（商业变体） | Could | 中 / 高 | 玻璃塔楼、整面竖向格栅、顶部退台或斜切 | 冷蓝灰 + 高光条 |

- **MVP 建筑资产只覆盖 3 类 Must 分区**（裁定 1）；公共服务 / 公园 / 办公建筑从 Must 移出，明确标 Should / Could，其图案编码亦不在首版必交范围。
- 玩家**不逐栋摆楼**（GDD R2 / P4 否决项）：建筑按"分区 + 密度"自动生长，因此美术侧需保证**同分区同密度档的多变体**在剪影上一致、仅在窗格 / 色彩 / 屋顶小构件上变化，避免玩家误以为是不同的机制对象。
- **时代符号（可选点缀，Should 级）**：玻璃幕墙、屋顶光伏板、绿化屋顶、充电桩、街头广告屏。每屏 ≤ 3 类，避免堆砌；**不含任何车辆类符号**。
- **明确排除**：蒸汽朋克管道、中世纪坡顶小镇、复古未来流线型、任何年代错置符号。

### 4.3 道路

- **MVP 仅 1 类基础道路**（GDD 5.1 Must）；干道 / 支路 / 快速路分级为 Should，届时由**宽度 + 中央分隔线 + 路缘**三级区分，不新增资产体系。
- 以正交网格为骨架；等距下覆盖：直道（两向）、90° 弯、T 字、十字、端头；用 **tile 拼接规则**组合，不为每种组合单独出图。
- 标线：车道虚线、斑马线、路口停止线、方向箭头，几何线宽 1–2px @1x；信号灯用几何符号（圆点三连），不做写实灯柱。
- 路口与建筑按 §2.1 同一 Y 轴排序，避免建筑压住斑马线。

### 4.4 植被与去实体化边界（锚点 5 / 裁定 5）

| 类别 | 造型规则 | 范围 |
|---|---|---|
| 通勤流量 | **不画逐辆车**：以线宽 / 亮度编码的路径线表达（§3.3） | Must |
| 植被 | 2–3 种几何冠形（圆团 / 多边形团簇 / 锥）+ 短圆柱树干；草地为微纹理色块，不用叶片贴图 | Must（成组，L0 合并为分区绿地色块） |

> **明确禁止（无 Could 期退路）**：**不制作车辆 3 型（小汽车 / 公交 / 货车）、不制作市民点状 / 胶囊人物、不制作任何逐个体仿真或实时车流粒子、不做车辆 / 市民沿路径插值动效**（锚点 5、GDD 5.1 Won't、9.3 已知取舍、OD-3 A 走「市民之声」文本路线）。本作的"城市在运转"由**通勤流线、指标变化与议题卡**承载，而非车流与人群演出。
> 相应地，§2.3 LOD 表、§8.3 动效清单、§9.3 图集划分、附录 A 资产清单均已清除车辆 / 市民相关条目。

## 5. 材质与光照

### 5.1 伪光照（Baked Lighting）

2D / 2.5D 下**不计算实时光照**，所有光照信息烘焙进纹理：

- **固定光源方向**：画面左上 45°，全项目一致，禁止出现方向矛盾的资产。
- **三分面明度阶梯**：顶面 100% / 亮侧 85% / 暗侧 70%（可按材质微调 ±5%），造型阶段即切分（§4.1）。
- **烘焙软投影**：椭圆 / 多边形软边投影贴片，随建筑占格缩放，不透明度 18–25%；**不使用实时阴影贴图**。L0 关闭，L2 可选开启。
- **接触 AO**（可选）：地块与建筑接触处一圈深色渐变贴片，仅 L2 启用。

### 5.2 昼夜 / 季节（范围：Could，非 MVP 强制 · 锚点 6 / 裁定 4）

> **MVP 只做单一「晴朗白天、明亮、干净、有秩序感」基调**（锚点 6，与 C-3 拍板一致）。概念 5.1 把季节 / 昼夜列为 Could、5.2 切片外明确「无季节昼夜」，因此**本节全部内容为 Could 期实现预案，不构成首版交付承诺，不得进入 Must 资产清单**。

预案（启用时）：不逐帧重绘，采用「全局叠色层 + 窗光层 + 背景渐变」三件套：

| 时段 | 全屏叠色（建议） | 窗光层 | 背景天空 |
|---|---|---|---|
| 晨 | 暖橙 `#FFD9A8` @ 8% | 少量淡入 | 浅橙 → 冷白渐变 |
| 昼（**MVP 默认，唯一启用**） | 无 / 中性 0% | 关闭 | 冷白 → 浅蓝 |
| 黄昏 | 橙紫 `#E88A5B` @ 14% | 渐变淡入 40% | 橙 → 灰紫 |
| 夜 | 深蓝 `#12224A` @ 30% | 全量点亮 | 深蓝 → 墨蓝 |

- 窗光用独立小图集点阵图（每建筑 3–8 个光点，按 LOD 控制数量）。
- 时段过渡为全屏叠色层 300–600ms 淡入淡出；"减少动态效果"开启时改瞬时切换。
- 不改变分区色 / 状态色语义明度，必要时对状态色单独做明度补偿，保证告警在夜景下仍达对比度线（§9.2）。

### 5.3 天气（范围：Could / 裁定 4）

> **整体为 Could，首版仅「晴」**。以下为后续启用预案，不进 Must。

仅 **晴 / 阴 / 雨 / 雪** 四种，全部由"轻量粒子 + 全屏叠色矩形"实现：

| 天气 | 实现 | 预算 |
|---|---|---|
| 晴 | 默认，无额外层（**MVP 唯一启用**） | 0 |
| 阴 | 冷灰叠色 @ 10% + 全局降饱和（叠色近似，不调 Shader） | 1 个 Sprite |
| 雨 | 屏幕空间雨丝 Sprite（循环位移）+ 地面微反光色块 @ 6% + 降对比 | ≤ 40 个雨丝实例 |
| 雪 | 建筑顶面 / 地面积雪叠片（复用轮廓裁切）+ 冷白叠色 @ 10% | 静态叠片，0 粒子 |

- 天气层在 L0 全部关闭；低性能档位（§9.4）默认关闭雨雪。

### 5.4 明确不做

实时动态阴影、多光源、逐像素法线 / 高光、SSAO / SSR / 景深 / 动态模糊 / 重度 Bloom、逐对象独立材质与 Shader 变体、自定义后处理管线。所有效果须退化为"贴图 + 叠色 Sprite + 少量粒子"，以契合 Cocos 3.x 2D 管线与鸿蒙手机端预算。环境动效克制（缓移云影、缓慢流线），服务于可读性而非氛围沉浸（锚点 6）。

## 6. UI 视觉

### 6.1 信息密度策略（锚点 4 · 硬规范 / 裁定 2）

城市建造天然高信息密度，但手机屏小 —— 采用 **分层显示 + 双态切换**：

| 态 | 显示内容 | 网格线 | 数据叠层 |
|---|---|---|---|
| **观赏态（默认）** | 城市本体 + **常驻 3 个全局指标：满意度 / 预算（资金）结余 / 周期（日期）** | 淡出 | 无（不叠分区色块 / 流量线 / 热力） |
| **决策态 / 规划态** | 在观赏态基础上叠加分区色块 + 图案编码 + 通勤流量线 + 热力 / 诊断层 | **显性** | 有，且一次只开一层 |

- **常驻指标硬约束（裁定 2）**：同屏 **≤3 个全局指标，且固定为满意度 / 预算结余 / 周期**。依据 GDD 支柱 P1「满意度是唯一计分板」，**人口只是过程量、不作计分板，不得进入常驻指标**；人口、预算明细、4 因子归因链、分区级差异一律降为次级面板，点击后展开。
- **「数据面板」定义（锚点 4 补充）**：**常驻状态条与底部工具条不计为数据面板**；但**同一时刻展开的详情 / 预算 / 诊断类面板最多 1 个**。诊断面板 / 预算面板 / 地块详情卡 / 议题列表共用同一槽位、**互斥出现**，切换时旧面板先退出。小地图、toast 亦不计为数据面板。
- **其他硬上限（GDD P4 / 锚点 4 / R3）**：待处理议题 **3±1 条**；菜单层级 ≤ 3；单次决策 ≤ 30 秒读懂、一次点按完成；**编码优先级：图标 > 数字 > 文字**。
- 两态切换建议 200ms 淡入淡出，须**明确可感**（锚点 1）；"减少动态效果"开启时改为瞬时。
- 次级信息收入可展开面板，遵循"选中 → 摘要卡 → 展开完整面板"两级，禁止一屏铺满表格。
- 数据可视化优先于文字堆砌：趋势用微型 sparkline、占比用细环 / 条，数值用等宽数字（§7.2）。

### 6.2 HUD 布局（手机竖屏 · Must）

```
┌─────────────────────────────┐  ← 系统状态栏 / 挖孔（安全区）
│ 城市名  🙂满意 💰结余 📅周期   │  顶部只读指标条（固定 3 项，不透明底）
├─────────────────────────────┤
│                             │
│      城市画布（等距世界）      │  ← 中央连续可视区，UI 覆盖率 ≤ 30%
│    [选中态 / 规划预览 / 流线]  │
│                             │
│  ┌──────────┐               │
│  │ 小地图    │ [单面板浮层]   │  ← 左下可折叠小地图 / 右侧唯一数据面板
│  └──────────┘               │
├─────────────────────────────┤
│  居住  商业  产业  道路  拆除  │  底部 1/3 拇指热区（3 类分区，大热区）
│      [ 结束本日 ]             │  ← 唯一主节奏按钮（OD-2 A 已拍板）
└─────────────────────────────┘  ← 底部手势条（安全区）
```

- **时间控件（OD-2 A 已拍板 / 裁定 3）**：**主动推进、默认暂停**。唯一主节奏控件是底部 **「结束本日」**按钮，点击结算一次 tick，思考时间无限。顶部**不放暂停按钮、不放倍速控件**；`×1 / ×2 / ×4` 自动播放为 **Should 期可选，不得进 Must**，若将来启用须显式标出当前档位。§8.1 动效体系不含倍速描述。
- 顶部：**只读**指标条，固定 3 项（满意度 / 结余 / 周期），不透明底。
- 底部：分区选择（**仅 3 类 Must 分区**）+ 道路 + 拆除 + 「结束本日」，为**最高频操作区**，热区最大（§6.5），全部落在底部 1/3 拇指区（锚点 7）。
- **议题列表 / 诊断面板**：GDD 5.1 列为 Must，二者与「地块详情卡 / 预算面板」共用同一个数据面板槽位，遵循 §6.1 互斥规则；议题卡用图标 + 短句 + 归因箭头，不用密集表格。议题列表以轻量贴边入口常驻，点击后展开为该时刻唯一数据面板。
- 通知 / 事件：顶部下方或右下轻量 toast，**不遮挡中央画布与底部工具区**，自动消失 + 可手动关闭。

### 6.3 折叠屏控显分离 / 平板（范围：Should · 非承诺）

> 依 GDD 6.2 H2 与 R6：**折叠屏 / 平板适配是 Should 级平台特性，全部为可选加分项、非承诺，不得进入 Must**。本节提前给出规范，一旦主理人排期即可直接落地，不代表本轮交付承诺。

| 形态 | 布局 |
|---|---|
| **折叠态（合盖）** | 等同 §6.2 手机竖屏布局（**折叠态回退规则**） |
| **展开态（上半屏地图 / 下半屏控制）** | **上半屏**：只放城市画布 + 极简只读指标条（固定 3 项），不放任何操作控件；**下半屏**：承载分区选择、「结束本日」、预算 / 议题 / 诊断面板、小地图等**全部交互控件**，可做双列 / 标签页。中间铰链区上下各留 ≥ 24dp 避让。 |
| **平板（横屏）** | 侧栏式：左侧城市画布（≥ 70% 宽）+ 右侧常驻双列面板，小地图固定在右下 |

- 展开态下半屏因面积充裕，可默认展开一级详情面板；但**仍须遵守"任一屏 ≤1 个数据面板"**（双列中一列常为导航 / 列表，不计为数据面板）。
- 上半屏画布的相机逻辑、LOD 阈值与手机态共用同一套，仅可视高度变化（§2.2）。
- **铰链 / 折痕避让**：不把关键控件、选中态、关闭按钮压在 hinge 区域；具体安全区与折叠区域接口**待程基岩核对 HarmonyOS API**（附录 D-2）。若预览版接口不稳定，降级方案为"固定上下分栏 + 手动留白 24dp"。

### 6.4 安全区

- 必须避让：系统状态栏、挖孔 / 刘海、底部手势导航条、折叠铰链 / 折痕区、平板多窗口分割线。
- HUD 根容器统一读取系统安全区后做 padding；**禁止硬编码固定偏移**。
- 展开态 / 多窗口 / 分屏切换时，布局须在**不重建场景**的前提下重排（纯 UI 层响应）。

### 6.5 字号与触控热区（锚点 7）

| 项 | 建议值 | 说明 |
|---|---|---|
| 最小正文 | ≥ 14sp 中文 | 低于此值在手机 + 中文笔画下不可读 |
| 关键数值 / 按钮 | ≥ 16sp | 满意度、结余、分区 Tab、「结束本日」 |
| 标题 | ≥ 20sp | 面板标题、城市名 |
| 文本缩放 | 跟随系统字号 100%–200% | 弹性容器 / 自动换行，**不截断、不重叠、不固定宽高**（§9.2） |
| 触控热区 | ≥ 44 × 44dp（锚点 7） | 相邻热区间距 ≥ 8dp；鸿蒙推荐值待程基岩核对 |
| 网格点选 | 吸附到格 + 选中态放大反馈 | 密集网格下降低误触；拖拽 / 长按须有点击替代路径（§9.2） |

### 6.6 反馈即时性 · 两级反馈（锚点 8 · 架构硬约束）

> **两级反馈为硬性要求**：
> 1. **即时可见**（落位、高亮、扣减、预览描边）—— 玩家操作后 **< 100ms** 响应，**不受低频 tick 约束**；
> 2. **tick 后可见**（指标变化、议题出现 / 消退、满意度归因）—— 跟随一次模拟结算更新。
>
> 严禁"点了没反应"的黑箱感（GDD R4 / V2 诊）。若把 UI 反馈也绑到 tick，会直接摧毁 Competence 与因果可读性。**主理人已确认本条与概念锚点 8 一致，并列为架构硬约束**；实现分层仍待程基岩确认（附录 D-3，唯一保留的架构确认项）。

## 7. 图标与字体

### 7.1 图标系统

- **栅格**：统一 **24 × 24 @1x 逻辑栅格**（复杂图标 48 × 48），安全留白 2px，关键轮廓对齐整像素，导出 @1x / @2x / @3x（或 SVG → 打包进图集）。
- **风格二选一且全项目统一**：推荐**填充式（solid）** —— 小尺寸、密集 UI、低对比底上辨识度优于线性；若选线性则统一 **2px 描边 + 圆角端点**。禁止混用。
- **圆角 / 端点 / 倾斜角统一**：与 §4.1 建筑圆角同一数值体系；分区图标使用**建筑轮廓剪影**，与 §4.2 剪影识别点一致（图标即资产的缩略）。
- **形状编码强制**：状态图标必须自带形状（✓ / ! / ✕ / 锁 / ↑ / ↓），不得只靠颜色（§3.4、§9.2），且不得借用分区图案；**分区图标须与图案编码同形**（锚点 7）。
- **图集**：全部图标打入 `UI 图集`（§9.3），同屏合批；禁止图标各自独立纹理。
- 图标不内嵌文字，文案一律走文本组件（便于多语言与文本缩放）。
- **不制作倍速 / 暂停图标**（裁定 3）；主节奏图标只有「结束本日」。

### 7.2 字体族

| 用途 | 首选 | 回退 | 备注 |
|---|---|---|---|
| 中文 UI | **HarmonyOS Sans**（系统默认） | 思源黑体 / Noto Sans SC | 无衬线黑体；禁止宋体等衬线用于 UI 数值 |
| 数字 / 拉丁 | HarmonyOS Sans 数字变体 | Roboto | **必须启用等宽数字（tabular figures）** |
| 字重 | Regular / Medium / Bold 三档 | — | 不引入更多字重，控制包体 |

- **等宽数字为硬性要求**：结余、周期、满意度等跳变数值若用比例数字会左右抖动，破坏密集 HUD 的稳定感（§6.1 数值滚动动效依赖此特性）。
- 数值滚动、sparkline、单位与千分位格式统一走同一格式化组件。
- **字体授权待确认**：HarmonyOS Sans 的打包 / 商用条款与思源黑体 OFL 合规性需法务确认（附录 D-5）。优先引用系统字体以避免打包体积与授权风险。

### 7.3 中文与多语言排版约束

- 中文按词 / 语义断行，做禁则处理（避免行首标点、孤字）；数值与单位间用窄空格，不留全角空格。
- 首版简中；**架构上预留繁中 / 英文**：所有文案容器按 **1.5–2× 长度弹性**设计，不写死宽度，不把文案烧进贴图。
- 本地化：数字千分位、货币符号、日期 / tick 格式、正负号位置由格式化层统一处理。
- 全横排，无竖排；文本方向切换（如未来 RTL）不在首版范围，但容器不假定左对齐写死。

## 8. 动效与 VFX

### 8.1 总原则：两类动效分离（锚点 8）

| 类别 | 触发 | 是否受 tick 约束 | 可关闭 |
|---|---|---|---|
| **即时 UI 反馈** | 玩家操作（划 / 拨 / 连 / 点「结束本日」） | 否，< 100ms 响应（§6.6） | 否（仅可减弱时长） |
| **世界状态动效** | 模拟结果 / 议题变化 | 跟随 tick 或平滑插值 | 是（减少动态效果） |

> **不含倍速自动播放**（OD-2 A 已拍板主动推进、默认暂停；裁定 3）。本动效体系只响应离散 tick 与玩家操作，不设连续时间轴。

环境动效克制（缓移云影、缓慢流线），服务于可读性而非氛围沉浸，不追求史诗演出（锚点 6、GDD 2.3 排除 Sensation）。

### 8.2 标准缓动与时长（全项目复用）

| 档 | 时长 | 曲线 | 用途 |
|---|---|---|---|
| Fast | 120ms | ease-out | 按压、Tab 切换、选中描边 |
| Base | 200ms | ease-in-out | 面板展开、层级切换、双态切换、规划落位 |
| Slow | 320ms | ease-out | 数值滚动、密度生长 |
| Fade | 300–600ms | linear | 昼夜 / 天气叠色过渡（Could） |

弹簧 / 回弹仅用于"规划落位完成"一处，overshoot ≤ 5%，避免卡通感（§1 P2）。

### 8.3 动效清单

| 动效 | 表现 | 时长 / 曲线 | 可关闭 |
|---|---|---|---|
| 规划落位（划分区 / 铺路） | 分区色块 + 图案 120–180ms 淡入铺开 + 落位描边 + 少量尘环（≤ 12 粒）；合法绿 / 非法红斜纹预览 | Fast–Base | 粒子可关，落位保留 |
| 拆除 / 改划 | 去饱和 + 收缩 + 旧图案淡出 | Base | 碎屑可关 |
| 「结束本日」结算 | 按钮按压 + 一次轻量全屏扫光，随后进入 tick 后反馈 | Fast | 扫光可关 |
| 密度生长（tick 后） | 建筑体块**纵向抽长**（scaleY 插值）+ 顶部一道扫光，不整块重建 | Slow | 扫光可关 |
| 数值变化（tick 后） | 等宽数字滚动（§7.2）+ 正 / 负向色 + 箭头形状编码 | Slow | 可关为瞬时跳变 |
| 议题出现 / 消退 | 议题卡滑入 + 图标脉冲；消退时淡出 | Base / 1.2s loop | **脉冲必须可关** |
| 状态告警 | 图标脉冲 + 颜色 + 形状三重编码 | 1.2s loop | **必须可关** |
| 选中地块 | 呼吸描边（主色 2px） | 1.6s loop | **必须可关**（转静态描边） |
| 通勤流量 | 沿路径的**线宽 / 亮度**变化（§3.3），不用粒子车流 | 持续 | 可关为静态标注 |
| 拥堵提示 | 路口语义色脉冲 + 形状标记 | 1.2s loop | **必须可关** |
| 昼夜 / 天气（Could） | 全屏叠色层淡入淡出 | Fade | 可关为瞬时 |

> **无「车辆 / 市民沿路径插值」动效行**（裁定 5 已删除）。

### 8.4 粒子策略（预算内）

- **单屏同时活跃粒子 ≤ 200（手机）/ ≤ 400（平板 / 折叠展开态）**；单个发射器 ≤ 12–24 粒；规划落位尘环 ≤ 12 粒。
- 优先用**预烘焙序列帧 / 少量 Sprite 插值**替代通用粒子系统；通勤流量、雨丝均按此实现，**不做实时车流粒子**（锚点 5）。
- 所有粒子贴图统一打入 `VFX 图集`，禁用逐粒独立材质 / 独立纹理。
- **粒子仅在 L1 / L2 启用，L0 全部关闭**（§2.3）；低性能档位进一步关闭雨雪与尘环。
- "减少动态效果"开启后：所有 loop 动效、粒子、相机缓动停播，仅保留必要的即时状态变化与静态反馈（§9.2）。

## 9. 可访问性与性能约束

### 9.1 可访问性分级

> **分级：Standard（标准级）起步，目标 Comprehensive（全面级）**（C-4 已拍板按推荐执行）
> 理由：城市建造**高度依赖颜色编码**（分区、状态、通勤），且锚点 7 明确要求"分区不得只靠颜色区分"；手机小屏 + 密集 UI 使文本缩放与 44dp 热区同为刚需。Basic 级不足以覆盖本品类风险；Comprehensive 的完整输入替代与三档色盲调色板可放到 Should 阶段升级。
>
> **本分级是 UX 规格与 `design/accessibility/accessibility-matrix.md` 的输入约束** —— 文策渊产出的 UX / 交互规格须显式引用本分级，并在验收项中包含 §9.2 矩阵（锚点 7）。**可访问性矩阵文件统一路径为 `design/accessibility/accessibility-matrix.md`，第二波由 art-director 产出**；此前在并行阶段使用的旧路径一律作废，不再引用。

### 9.2 特性矩阵与验收标准

| 特性 | 首版 Standard（Must） | 升级 Comprehensive（Should） | 验收标准 |
|---|---|---|---|
| 色盲友好 | 分区色 **+ 图案编码 + 图标 / 文字标签**（锚点 7）；状态色配形状编码（✓/!/✕/锁/↑↓），且状态形状不得借用分区图案（§3.4 规则 4）；配色经 deuteranopia / protanopia / tritanopia 模拟校验 | 三档色盲专用调色板可切换、图案强度可调 | 去色 / 三型色盲模拟下，①分区与状态仍可 100% 区分；②**状态色 vs 分区色不混淆**（新增，裁定 8）：把任一状态图标叠在任一种分区填充上，仍可判读状态且不被误认为分区变体 |
| 对比度 | 正文 ≥ 4.5:1，大字与 UI 边界 / 图标 ≥ 3:1；顶 / 底 HUD 不透明底（§6.2）；状态色为 L 40–50 深色前景，在浅底上天然达标 | 高对比模式（图案不透明度 30% + 1px 深色描边） | 全时段（含 Could 期夜景叠色）与全部天气下自动校验通过 |
| 动效可关闭 | "减少动态效果"：关闭所有 loop / 粒子 / 相机缓动，双态与层级切换改瞬时（§8.4） | 逐项动效强度调节 | 开启后无任何循环动画，信息不丢失 |
| 文本缩放 | 跟随系统字号 100%–200%，弹性布局不截断 / 不重叠（§6.5） | 大字号专用紧凑布局 | 200% 下所有面板可完整滚动阅读 |
| 触控热区 | ≥ 44×44dp（锚点 7），间距 ≥ 8dp；网格吸附 + 选中放大 | 热区可视化调试开关 | 全部可点元素达标 |
| 输入替代 | 全功能触控可达；长按 / 拖拽提供点击替代；不设需精确快速连点的操作 | 更完整的输入替代路径与操作时长放宽（**不引入 PC 式快捷键**，GDD 5.1 Won't） | 仅用触控即可完成全部主流程；单手可操作 |
| 多通道反馈 | 所有状态变化 ≥ 2 个通道（颜色 + 形状 / 文字 / 动效） | 议题播报文字等价、完整字幕 | 单一通道失效时信息仍可达 |
| 音频冗余 | 所有音频提示须有视觉等价物（与阮和鸣协同，本圣经只提约束） | 完整字幕 / 视觉提示强度调节 | 静音状态下游戏可完整进行 |
| 性能可降级 | 低 / 中 / 高 三档性能位（§9.4） | 自动按帧率动态降档 | 低档位下仍满足以上全部可访问性项 |

### 9.3 纹理与图集策略

| 项 | 建议值 | 说明 |
|---|---|---|
| 单张贴图 / 图集 | ≤ **2048 × 2048** | 兼顾中低端鸿蒙机 GPU 上限，待程基岩核对 |
| 压缩格式 | **ASTC**（首选）/ ETC2 回退；不透明底可用 RGB565 | 以 Cocos 鸿蒙导出实际支持为准（附录 D-1） |
| UI 图标 / 文字图集 | RGBA8888 或不压缩 | 保清晰度，避免压缩伪影 |
| 常驻纹理内存 | ≤ **80–120 MB**（中端机），峰值 ≤ 150 MB | 真机实测校准 |
| 图集留白 | ≤ 10%，禁用超大透明边距 | 定期做图集打包审计 |
| 分包加载 | `UI 图集` 常驻；建筑 / 地形 / VFX 按 LOD 或分区分包，禁止一次性全载 | 控制首屏与峰值内存 |

**图集划分（按同屏合批优先）**：`UI` / `UI-图案编码` / `地形地块` / `道路` / `建筑-居住` / `建筑-商业` / `建筑-产业` / `建筑-公共服务(Should)` / `植被` / `VFX` / `昼夜窗光(Could)` / `天气(Could)`。
- 同屏同图集优先、相邻 UI 层级尽量同图集，避免跨图集交替绘制打断 Cocos 自动合批。
- 面板 / 按钮一律 **9-slice 九宫格**，减少切片数量；LOD 三档资产打入同一图集（§2.3）。
- **不存在车辆 / 市民资产，故不设对应图集**（裁定 5）。

### 9.4 帧率、DrawCall、包体与内存（建议基线）

| 指标 | 建议值 | 备注 |
|---|---|---|
| 目标帧率 | **30fps 稳定基线**，复杂场景不低于 25fps | 低频 tick + 半静态画面，不追 60fps；交互反馈不受帧率影响（§6.6） |
| DrawCall · L0 远景 | ≤ 30 | 关闭粒子与细节 |
| DrawCall · L1 常规（手机） | **≤ 60–80** | 主验收场景 |
| DrawCall · L2 近景 / 复杂 | ≤ 120 | 平板 / 折叠展开态可放宽至 ≤ 150 |
| 应用总内存 | ≤ 300–400 MB（中端机） | 含纹理 + UI + 模拟数据 |
| 首包体积 | ≤ 150–200 MB，美术资源占比 ≤ 60% | 鸿蒙应用包上限待程基岩核对 |
| 后续资源 | 扩展分区 / 建筑包按需下载（若平台支持） | 控制首包 |

- 网格规模按 GDD 5.1 建议 24×24 ~ 32×32；建筑 / 地块尽量共用**同一材质 + 同一图集**触发合批；UI 层级扁平化；**禁用逐对象独立材质与 Shader 变体**。
- **性能档位**：低档关闭天气粒子、夜间窗光、接触 AO、全部 VFX 粒子，并下压 LOD 阈值（更早进入 L0 表现）；中档为默认；高档开放 §5.3 全套。
- 所有数字为**建议基线**，须由程基岩在 DevEco Studio + 真机（含折叠屏展开态、低档位机型）实测后转为硬指标（附录 D-1）。
