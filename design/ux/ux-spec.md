## 1. 设计目标与硬约束

### 1.1 目标

把 01~05 的系统输出，变成手机上**30 秒能读懂、一次点按能决策、结果能复盘**的交互：常驻只读、次级可展、诊断可追。

### 1.2 硬约束（不可突破）

| # | 约束 | 来源 |
| --- | --- | --- |
| C1 | 常驻 HUD **≤3 个全局指标**：**满意度 / 预算结余 / 周期**；**人口是过程量，进次级面板** | 概念 P1、3.3、5.1；本轮主理人指令 |
| C2 | **默认暂停、主动推进**：点「结束本日」结算一次 tick；**首版不得出现倍速控件**，×1/×2/×4 自动播放为 Should | **OD-2 A 已拍板**（概念 8.0） |
| C3 | 单次决策 **30 秒内读懂、一次点按完成**；同屏 ≤1 个数据面板、菜单 ≤3 层 | 概念 P4、锚点 4、9.1 R3 |
| C4 | **两级反馈**：即时（<100ms）+ tick 后；UI 反馈**不受 tick 约束** | 概念锚点 8；美术圣经 §6.6 / 附录 D-3 |
| C5 | 折叠屏 / 平板双栏**仅标 Should，不进 Must**；鸿蒙 H1~H4 全部可选非承诺、不得进 Must、须架构确认后才排期 | 概念 5.1 / 6.2（G5） |
| C6 | 切片外 9 项（公交 / 政策卡 / 地价 / 多道路等级 / 危机事件 / 跨设备 / 折叠屏双栏 / 季节昼夜 / 成就 / 分享）不得出现在本规格 | 概念 5.2 |
| C7 | 可访问性采用美术圣经 **v0.2 §9.1 Standard（标准级）起步**，验收须包含 **v0.2 §9.2 特性矩阵**全部条目（含新增「状态色 vs 分区色不混淆」） | 美术圣经 §9.1 明确「本分级是 UX 规格的输入约束」 |

### 1.3 与美术圣经 **v0.2** §6.2 / §6.1 的一致性核对

美术圣经已升级 **v0.2** 并按主理人 10 条裁定完成收敛：其 §6.2 线框现为「只读 3 项指标 + 3 类分区 + 唯一『结束本日』控件」、§6.3 折叠屏标 Should、§9.1 / §9.2 亦已同步。**本规格与 v0.2 逐条一致，无残留冲突**。下表记录 v0.1 → v0.2 的收敛结果，仅作追溯，**不作为现状描述**：

| --- | --- | --- | --- |
| 常驻指标 | 资金 / 人口 / 满意度 / 时段 / 速度（3–5 项） | **满意度 / 预算结余 / 周期（3 项）** | C1；人口为过程量（P1） |

## 2. 竖屏 HUD 信息架构

### 2.1 线框（文字版 · 手机竖屏 Must）

```
┌──────────────────────────────────┐ ← 系统状态栏 / 挖孔（安全区 · A-9 已确认）
│ 🙂 满意度 72  💰 结余 +1,240  📅 周期 3/7 │  顶部状态条（不透明底，仅 3 个常驻指标）
├──────────────────────────────────┤
│                                  │
│        城市画布（2:1 dimetric 等距）│  ← 中央连续可视区，UI 常驻覆盖率 ≤ 30%
│        规划态：网格线显性           │     （美术圣经 §2.4）
│        观赏态：网格线淡出           │
│        [选中态 / 建造预览]          │
│                                  │
│  ┌────────────────────┐        │
│  │ 议题 3 条 ▸（贴边入口）│        │  ← 3±1 条计数；点开才占唯一数据面板槽位
│  └────────────────────┘        │     （美术圣经 §6.2 面板互斥规则）
├──────────────────────────────────┤
│ 居住  商业  产业  道路  拆除       │  ← 底部建造 Tab（拇指热区，5 类）
│        [ 结束本日 ]               │  ← 唯一主 CTA，一次点按 = 一次 tick
└──────────────────────────────────┘ ← 底部手势条（安全区）
```

**明确没有**：倍速控件、人口常驻、时段 / 昼夜切换、**常驻展开的小地图**、悬浮多面板、成就 / 分享入口、跨设备入口。

> 美术圣经 v0.2 §6.2 的「左下可折叠小地图」为**贴边可折叠**控件，不常驻展开、不占数据面板槽位，与本规格不冲突；议题列表同样以**轻量贴边入口**常驻，点击后展开为该时刻唯一数据面板。议题列表 / 诊断面板 / 地块详情卡 / 预算面板**共用同一个数据面板槽位**，遵循 §6.1 互斥规则。

### 2.2 三层披露（锚点 4「分层显示」的落地）

| 层 | 内容 | 触发 | 同屏面板数 |
| --- | --- | --- | --- |
| **L0 常驻** | 3 个指标 + 议题条（折叠态）+ 底部 Tab + 「结束本日」 | 默认 | 0 个数据面板 |
| **L1 次级面板** | 点指标展开：人口 `P_t`、4 因子 `f_i`、收支明细（`I / C_b / C_m / B`）、周期详情 | 一次点按 | **≤1 个** |
| **L2 诊断面板** | 点议题展开：`primary_factor`、`ΔS_i`、明细（哪条通勤线 / 哪片覆盖 / 哪笔投入）、建议动词 | 一次点按 | **≤1 个** |

- L1 与 L2 **互斥**：展开其中一个即收起另一个，绝不并排（P4 / 美术圣经 §6.1「禁止一屏铺满表格」）。
- 编码优先级：图标 > 数字 > 文字；状态一律「颜色 + 形状 + 文字」多通道（美术圣经 §3.4 / §9.2）。
- 数字使用等宽数字（美术圣经 §7.2），避免跳变抖动。

### 2.3 常驻三指标定义

| 指标 | 来源 | 单位 | 更新时机 | 点击行为 |
| --- | --- | --- | --- | --- |
| 满意度 | 01 `S_t` | `分` `[0,100]` | tick 后（S8） | → L1 四因子面板 |
| 预算结余 | 04 `B_t` | `CU` | 周期结算后（S7/S8） | → L1 收支明细 |
| 周期 | 04 周期进度 | `周期 k/K` | tick 后 | → L1 周期详情 |

> 人口 `P_t [person]` 与岗位 `J_t [job]` **只在 L1 出现**，且不得附带任何里程碑 / 奖励（P1、GDD 02 AC-M3）。

## 3. V1 → V9 交互流程与两级反馈

### 3.1 动词到界面的映射

| 动词 | 入口 | 玩家动作 | 即时反馈（<100ms） | tick 后反馈 |
| --- | --- | --- | --- | --- |
| **V1 读** | L0 顶部状态条 / 议题条 | 扫一眼 | 数值稳定显示、无延迟 | — |
| **V2 诊** | 点议题卡 / 点 `S` | 一次点按 | L2 诊断面板展开（120–200ms，美术圣经 §8.2） | — |
| **V3 划** | 底部 Tab → 画布框选 / 点选 | 一次点按 + 一次落位 | 分区色块 + 图案编码落位、合法/非法预览 | `P_t / J_t / S` 才变化 |
| **V4 拨** | L1 收支面板 → 投入项 | 一次点按 | 扣减预览、`I_f` 高亮 | `f_f / S / B` 才变化 |
| **V5 连** | 底部「道路」Tab → 画布 | 一次点按 / 一次拖拽（须有点击替代路径） | 路段流线即时更新 | `T_c / f_c / f_s` 才变化 |
| **V6 推** | **「结束本日」按钮** | **一次点按** | 按压态 + 按钮进入「结算中」禁用态 | 触发一次完整 tick 结算 |
| **V7 察** | L0 全屏 | 看 | — | 3 指标变化、议题出现/消退、流线三态变化、市民之声文本 |
| **V8 调** | 回到 V3/V4/V5 | 一次点按 | 同上 | 下一 tick 后见效 |
| **V9 兑** | 周期末 | 结算自动触发 | 解锁反馈（一次性） | 新增可用区域、新规划目标 |

### 3.2 两级反馈契约（C4）

| 级别 | 触发 | 时限 | 表现 | 依据 |
| --- | --- | --- | --- | --- |
| **即时 UI 反馈** | V1/V2/V3/V4/V5、切 Tab、选中、按钮按压 | **< 100ms** | 落位、高亮、描边、按压态、扣减预览、面板展开 | 美术圣经 §6.6；**不受模拟 tick 约束** |
| **tick 后模拟反馈** | V6 推 → V7 察 | 一次结算完成后 | `S / B / 周期` 变化、议题增删、流线三态、市民之声 | 概念锚点 8；GDD 01 的 S8 |

> **实现分层（美术圣经附录 D-3；**A-8 已确认**）**：UI 反馈与低频模拟必须分层，若 UI 反馈误绑 tick 会出现「点了没反应」。架构结论（`docs/architecture/architecture.md` §11.6 A-8 / ADR-004）：双通道 + 乐观视图 + VM，通道 A 帧内 <100ms 与 tick 无关、通道 B 跟随 Δ/事件，UI 零写权威状态；美术圣经附录 D-3 已据此关闭。本规格只提出体验约束，**不下技术结论**。
> 「减少动态效果」开启时：即时反馈保留**静态**描边 / 按压色（不消失），tick 后反馈改为瞬时跳变（美术圣经 §8.3 / §9.2）。

### 3.3 30 秒决策 / 一次点按的可测判据（C3）

| 判据 | 阈值 |
| --- | --- |
| 读懂 + 决策总时长 | `V1 读(5–10s) + V2 诊(10–20s) + 单个决策动词(10–20s) ≤ 30 s` |
| 单次决策点按数 | **1 次**（框选视为 1 次连续手势；须提供点击替代路径，§9.2） |
| 菜单深度 | **≤ 3 层**（L0 → L1 → L2） |
| 同屏数据面板 | **≤ 1 个** |
| 常驻指标 | **= 3 个**（C1） |
| 活跃议题 | **2 ~ 4 条**（3±1，GDD 05） |
| 跨屏记忆 | 诊断所需数据必须在当前面板内可见，**不得要求玩家记住上一屏数值** |

## 4. 关键屏幕 / 组件规格

### 4.1 「结束本日」按钮（**OD-2 A 的核心控件**）

| 项 | 规格 |
| --- | --- |
| 位置 | 底部拇指热区（底部 1/3），主 CTA，与建造 Tab 同区但视觉最高优先级 |
| 热区 | ≥ `48 × 48 dp`（取华为官方 2.1.3.3 推荐值 48vp，官方**必须**下限 40vp；S-12 由 44 上调），相邻控件间距 ≥ `8 dp`（**8dp 间距为本项目设计决策，非官方条文**；官方仅有 8vp 网格系统。美术圣经 §6.5 / §9.2） |
| 标签 | 文字「结束本日」+ 图标，**不单独依赖颜色**；禁用态加锁形 / 灰（形状编码） |
| 语义 | **一次点按 = 一次 tick 结算**；默认暂停、思考时间无限、无自动推进 |
| 状态 | `可点` → `结算中`（禁用，防重复） → `可点`；周期末追加一次结算 + 达标判定 |
| **明确禁止** | ❌ 倍速控件（×1 / ×2 / ×4）❌ 自动播放开关 ❌ 倒计时条 ❌ 离线推进提示 ❌ 任何「等待 / 挂机」暗示 |
| Should（不在首版） | ×1 / ×2 / ×4 自动播放（概念 5.1 / OD-2 A 拍板口径） |
| 边缘 | 结算过程中重复点按 → 忽略或只排队一次，**不得结算两次**（**A-1 已确认**：P0 InputGate 幂等键防重复点按） |

### 4.2 议题列表（消费 GDD 05）

- 条数 **2~4**；超出时按 `priority` 保留前 4 并**同类合并 + 折叠**，不堆叠、不新增面板。
- 每条卡 = 标题 + 状态形状图标（⚠ / ! / ✕ / ✓ / ↑↓）+ 一句摘要；点按 → L2 诊断面板。
- 位置：中央画布侧下浮层，**不遮挡画布主体与底部 Tab**（美术圣经 §6.2 通知位原则）。
- 状态变化多通道：颜色 + 形状 + 文字（§9.2）。

### 4.3 诊断面板（消费 GDD 01 / 05，支撑 AC2）

- 内容固定四段：**主因因子**（`f_c/f_s/f_e/f_f`）→ **贡献量** `ΔS_i [分/tick]` → **明细**（哪条通勤线 / 哪片覆盖不足 / 哪笔投入 / 哪笔维护费）→ **建议动词**（V3 划 / V4 拨 / V5 连，一次点按直达）。
- 一次只展开一个面板；与 L1 次级面板互斥（2.2）。
- **禁止**无来源的通用提示；`cause_ref` 为空时只允许 `TUTORIAL` 卡并明确标注（GDD 05 E1）。
- 归因数据只读，面板不写回任何模拟状态（GDD 05 AC-I7）。

### 4.4 主菜单 / 暂停

- 主菜单、独立暂停菜单**不在本轮 Must 范围**（垂直切片只要求「手机竖屏可完整通关」）；若需，按 Should 处理并由主理人排期。
- 「暂停」在 OD-2 A 下是**默认态**，因此不需要独立暂停按钮；切后台时「冻结 + 存一次」**已由 A-7 确认**（`docs/architecture/architecture.md` §11.6 / §5 / ADR-003，OD-2 A 下无需后台权限）。

## 5. 折叠屏 / 平板（**仅 Should，不进 Must**）

- 本规格的 **Must 只有手机竖屏**（C5 / 概念 5.1）。美术圣经 §6.3 的「展开态上半屏画布 / 下半屏全部控件」、§6.4 安全区规则，在本项目中**整体标注为 Should**，不进入首个冲刺 DoD。
- 折叠态（合盖）**等同 §2.1 手机竖屏布局**，不构成额外交付。
- 铰链 / 折痕避让、多窗口与分屏重排、系统安全区接口 **A-9 已由 `docs/architecture/architecture.md` §11.6 / §8 / §11.3 确认（有条件可行、不阻塞首版）**：LayoutProfile + 形态回退状态机 + 降级 4 条（启发式宽高比 / 手动留白 24dp / 整体安全容器内缩 / 纯 UI 重排），平台适配层隔离预览版接口，**须真机验证后方可排期**；与美术圣经附录 D-2 的降级路径一致。降级方案由美术 / 架构侧确认，本规格不自行定义技术方案。
- 平板横屏侧栏布局同为 Should；**不因形态差异新增任何玩法或指标**（C6）。

## 6. 可访问性规格（显式引用美术圣经 §9.1 与 §9.2）

### 6.1 采用的分级（**美术圣经 §9.1 原文口径**）

> 本 UX 规格**显式引用并采用** `design/art/art-bible.md` **v0.3 §9.1「可访问性分级」** 的裁定（**S-12 版本联动**：上游已升 v0.3；分级裁定本身未变，v0.3 的数值变更仅为热区 44→48dp）：
> **「分级：Standard（标准级）起步，目标 Comprehensive（全面级）（C-4 已拍板按推荐执行）」**。
> 理由（§9.1 原文）：城市建造**高度依赖颜色编码**（分区、状态、通勤），且锚点 7 明确要求「分区不得只靠颜色区分」；手机小屏 + 密集 UI 使文本缩放与 48dp 热区同为刚需。Basic 级不足以覆盖本品类风险；Comprehensive 的完整输入替代与三档色盲调色板可放到 Should 阶段升级。
> §9.1 同时明确：**「本分级是 UX 规格与 `design/accessibility/accessibility-matrix.md` 的输入约束 —— 文策渊产出的 UX / 交互规格须显式引用本分级，并在验收项中包含 §9.2 矩阵（锚点 7）」**，并规定可访问性矩阵统一路径为 `design/accessibility/accessibility-matrix.md`、第二波由 art-director 产出，此前旧路径一律作废。本节与第 8 节即为此要求的落地。

### 6.2 §9.2 特性矩阵（**v0.2 原文完整引用，作为本规格的 Must 约束**）

> **S-12 版本联动注**：本表**「触控热区」行**已按 `art-bible v0.3` 同步为 **48×48dp**，故该行不再是 v0.2 原文；其余单元格仍为 v0.2 原文。历史版本标签保留，避免抹除引用沿革。

## 7. 边缘情况（≥3 类）

| # | 边缘情况 | 处理原则 |
| --- | --- | --- |
| E1 | **活跃议题 > 4 条** | 按 `priority` 保留前 4 + 同类合并折叠；不新增面板、不遮挡底部 Tab（GDD 05 E2） |
| E2 | **即时反馈与 tick 结果同帧到达** | 即时反馈优先（<100ms），tick 结果排队到紧邻的下一帧刷新；不得出现「先跳数值再落位」的时序倒置 |

| E4 | **「减少动态效果」开启** | 即时反馈保留静态描边 / 按压色（信息不丢失），tick 后改瞬时跳变；关闭所有 loop / 脉冲 / 缓动（§9.2） |

| A-2 | tick 间快照与归因链的存储 | 支撑 L2 诊断面板的 `ΔS_i` 与明细可追溯、可随回退一致回滚 | **可行**：自包含 `TickSnapshot` 含 `t−1`/`t` 双帧 + `Δ_t` + 归因链（含通勤线明细）+ 命令溯源；结算时记录、查询只读不重算；落点 §4.1~§4.3 / ADR-002 / ADR-003 | **已确认** |
