### 1.1 受试者招募条件

| 项 | 规则 |
| --- | --- |
| 样本量 | `<N_playtest>` 名（测试侧占位，需用户 / 主理人确认，见 `tests/test-strategy.md` §10.2 / §13 O-2 / O-4） |
| 纳入 | 年满 18 岁；**从未见过 HC-01 任何版本**、未读过 `design/` `docs/` `production/` 任一文档、未参与任何内部评审；有智能手机日常使用经验；能独立完成一次 10 分钟以上的会话；自述色觉 / 视力 / 触控能力正常或已矫正；签署知情同意（`tests/evidence/<batch>/playtest/<subject-id>/consent.md`） |

### 1.2 主持脚本（逐字固定，不得临场发挥）

| 阶段 | 主持话术 / 动作 |
| --- | --- |
| 交付前 | 设备已安装待测 HAP、已登录、**全新存档**、系统字号 100%、动效开关默认、音频正常、手机竖屏；桌面与通知栏清理干净；录屏与计时工具就绪 |
| 开场（唯一允许的话术） | 「这是一次游戏体验测试。请像平时玩一款新游戏那样开始，全程按你自己的想法操作。过程中我不会解释规则，也不会回答关于玩法的问题。遇到问题请继续尝试，或随时说『我想结束』。全程录屏与计时，仅用于研究。」 |
| 交付 | 把设备交到受试者手中，**启动录屏与计时**，主持人退到受试者视线之外；不提供说明书、教程卡、截图、网页或任何外部说明 |
| 进行中 | 保持沉默；不观察式引导（不凑近看屏、不重复注视某一控件）；仅在 §1.3 三类情形干预 |
| 收尾 | 界面首次出现「首个市政周期结算完成」可读取结果，或达到 10 min 上限 → 停止计时 → 进入 §1.5 事后访谈 |
| 记录 | 全程填写 §1.4 观察记录表；每次干预记时间戳、原因、证据编号 |

### 1.3 不得提示的规则（主持人禁用清单 · 命中即本次会话判 INVALID）

1. 不得解释「分区—通勤—满意度」因果，不得说出 4 因子名称（`f_c` / `f_s` / `f_e` / `f_f`）或「满意度 / 覆盖 / 环境负荷 / 财政投入」的机制含义。
2. 不得提示点「结束本日」、不得提示哪里是诊断面板 / 议题卡 / 预算面板 / 建造 Tab。
3. 不得提示分区、路网、密度、预算如何搭配；不得回答「我该做什么」「这样对吗」类问题，统一回复「按你自己的想法继续」。
4. 不得用眼神、手势、重复注视、身体朝向引导；不得对犹豫 / 错误操作给予肯定或否定反馈。
5. 不得展示任何上游文档、内部截图、示意图或代操作设备。
6. **允许干预的仅三类情形**：① 应用崩溃 / 无法继续（记 `INVALID`，须更换会话重测并记 S1 缺陷）；② 受试者明确说「我想结束」（记 `INVALID`，单独统计放弃率）；③ 达到 10 min 计时上限（记 `FAIL`）。三类以外的任何干预 → 本次会话 `INVALID`。

### 1.5 事后访谈判据（因果理解，逐条可判定；提问不得含提示）

| # | 开放式提问（逐字） | PASS 判据 | FAIL 判据 |
| --- | --- | --- | --- |
| Q1 | 「请用你自己的话说说，你刚才做了什么、城市里什么变了、为什么会变。」 | 自发提及「分区位置 / 道路连接」与「通勤 / 到达时间」中**至少 1 项**，并把它与「满意度 / 市民评价」建立因果关联（说出方向即可，如「路没连好，大家不满意」） | 仅说「我点了按钮，分数变了」；或只描述外观 / 数值而不涉及因果 |
| Q2 | 「如果重来一次，你会先做什么、为什么？」 | 回答含「先规划位置 / 先连路 / 先留预算」等与因果有关的取舍 | 仅外观偏好（颜色 / 建筑好看）或「不知道」 |
| Q3 | 「你看到分数下降时，是怎么找到原因的？」 | 能说出通过诊断面板 / 议题卡读到**具体原因**（哪条通勤线 / 哪片覆盖不足 / 哪笔投入） | 「猜的」「不知道」「没注意」 |
| Q4 | 「有没有哪次操作后你觉得没反应或看不懂？」 | 未命中可复现的「点了没反应」 | 命中且可复现 → 记 S2 缺陷并关联 `CR-4` / `MR-08` |

**综合判定规则**：Q1 必须通过；Q2 / Q3 至少 1 项通过；Q4 不得命中可复现的黑箱反馈 → 该受试者「理解因果」判 PASS。样本级结论按 `<N_playtest>` 与通过比例阈值（开放项 O-2）汇总，逐受试者原始记录留存。访谈全程录音 / 转写，存 `tests/evidence/<batch>/playtest/<subject-id>/interview.md`。

### 1.6 计时口径（AC1 专用）

| 项 | 规定 |
| --- | --- |
| 起 `T_start` | 设备交到受试者手中、开场话术说完、录屏与计时启动的瞬间 |
| 止 `T_end` | 界面**首次**出现「首个市政周期结算完成」可读取结果（达标 / 未达标可回退重试）的那一帧；10 min 内未出现则 `T_end` = 10 min 且判 FAIL |
| 主判据 | `T_wall = T_end − T_start ≤ 10 min`，**包含暂停态思考时间** |
| 为何包含 | OD-2 A「思考时间无限」是**机制层允许**（不强制推进、不设倒计时、不惩罚挂机），不是体验层目标；AC1 的 10 min 是 `design/concept/game-concept.md` §5.2 / §3.3 的**体验上限**。若剔除思考时间，任何玩家都可把有效时长压到阈值内，AC1 会退化为永远 PASS 的空洞判据。完整论证与双指标口径见 `tests/test-cases/AC4-session-length.md` §1.2 |
| 辅助指标 | `T_active` = 剔除单段 ≥ `<T_idle>` 的静止无操作间隔后的时长，**仅用于归因，不改变主判据** |
| 外部中断 | 来电 / 切后台 / 设备异常段单独记录并从 `T_wall` 剔除，但须**更换会话重测一次**；中断不得计入「思考时间无限」的豁免 |
| 原始数据 | `tests/evidence/<batch>/timing/<TC-ID>_wall.csv`，字段：`T_start` / `T_end` / `T_wall` / `T_active` / 各静止段起止 / 各外部中断起止 / `tickId` 序列 / V6 点按次数 |

| 测试数据 | 空城（`P_t = 0` / `J_t = 0` / 全 EMPTY）、全图单一分区、路网不连通 / OD 不可达、`q/cap` 超饱和、`B_t < 0` 连续多周期、`C_b > B`、`I_f = 0`、`S` 触 0/100、6 个同时触发信号、锁定区操作、结算中连点、200% 字号、L1/L2 同时请求、去色 / 三型模拟、回退与解锁同帧 |

**编号步骤**

1. 逐类注入上表边缘初态，各跑 1 次完整 P0~P8 结算。
2. 每类检查输出中是否出现 `NaN` / `∞` / 除零 / 负收入 / 崩溃 / 中断。
3. 检查兜底值：不可达 → `T_max`；`Σ q_od = 0` → `T_c = 0`；`Σ w_g = 0` → `f_s = 0`；`P_t = 0` → `f_f = 0`；`ρ` 走 `max(J, ε)`（GDD 01 E3 / 02 E1,E6 / 03 E1,E5,E7 / 04 E2）。
4. 构造 6 个同时触发信号，检查 `n_issue` 与面板数。
5. 锁定区执行一次编辑，检查是否拒绝且不扣费（GDD 02 E3）。
6. 200% 字号下去色 / 三型模拟跑一轮；L1 与 L2 同时被请求一轮。
7. 结算中连点两次「结束本日」；构造回退与解锁同帧一轮。

**预期结果（可观测 / 可判定）**

- E1 所有边缘初态结算**不中断**；输出中 `NaN` / `∞` / 除零 / 负收入命中数 = 0；`S` 恒 ∈ [0,100]；`B` 恒为有限数（AC-F6 / AC-M6 / AC-E7 / AC-I8）。
- E2 步骤 3 各兜底值与 GDD 01 §4.1 / 03 §3.2 逐项相等；不可达时 `unreachable = true` 且生成可诊断议题（AC-T3）。
- E3 6 信号同时触发时 `n_issue ≤ 4`，超出部分同类合并 + 折叠且**不新增数据面板**（AC-I2 / UX E1）。
- E4 锁定区编辑被拒、即时非法反馈可见、`Cell` 不变、`B` 不扣减（02 E3）。
- E5 `S` 触 0/100 时归因链按钳制前主项记录并标注「已达上下限」（01 E4）。
- E6 结算中连点只结算 1 次（UX E5）；回退与解锁互斥、不同帧发生（04 E7）；200% 下无截断 / 重叠且仍单屏 ≤1 数据面板（UX E3 / E8）。
