## 1. 计时口径裁定（**本用例集最关键的一节**）

### 1.1 冲突陈述

- **OD-2 A**（`design/concept/game-concept.md` §8.0 / §8.2）：「主动推进制：**默认暂停**，玩家点『结束本日』结算一次 tick，**思考时间无限**（棋类 / 解谜感）」。
- **AC4 / §3.3**：「手机上 **5–12 min** 完成一个完整中循环 + 看得见进展；平板/折叠屏可延长到 20–30 min 完成一个宏循环。**超出即视为节奏设计失败**」。
- 二者表面冲突：若计时剔除暂停态思考，则「思考时间无限」会让 AC4 的 5–12 min 变成**永远可满足**的空洞判据；若计时包含思考，又可能与「思考时间无限」的机制承诺相抵触。

### 1.2 裁定（明确回答「是否包含暂停态思考」）

> **裁定：AC4 的主判据 `T_wall` 采用「会话墙钟时长」，即从会话起点到中循环闭环终点的真实经过时间，包含暂停态思考时间。**
> 另设辅助指标 `T_active`（剔除单段 ≥ `<T_idle>` 的静止无操作间隔），**仅用于归因与慢 / 快分类，不改变 PASS / FAIL 主判据**。

| 项 | 规定 |
| --- | --- |
| 主判据 | `T_wall = T_end − T_start`，**含暂停态思考**；AC4 PASS 要求 `5 min ≤ T_wall ≤ 12 min` |
| 辅助指标 | `T_active = T_wall − Σ(单段 ≥ <T_idle> 的静止无操作段) − Σ(外部中断段)`；只写入报告、只用于分类与归因 |
| 起 `T_start` | 会话开始事件：新会话 = 设备交付 + 开场话术 + 录屏计时启动；复用会话 = 主持人明确宣布「本段计时开始」的瞬间。**不得**从「议题首次出现」倒推起点（避免截断掉读与诊断时间） |
| 止 `T_end` | 一条议题首次进入 `CLOSED` 或 `CONVERTED` 且 §2「可见进展」判据确认成立的那一帧；若 12 min 内未出现，记 `T_end` = 12 min 并进入 §1.4 分类判定 |
| 外部中断 | 来电 / 切后台 / 设备异常 / 主持人干预段单独记录并从 `T_wall` 剔除，但须**更换会话重测一次**；中断不得计入「思考时间无限」豁免 |
| 平板 / 折叠屏 | 仅作为**性能测量形态**（`tests/test-strategy.md` §4.2）；AC4 的 5–12 min 判定以**手机竖屏**为唯一 Must 形态，不把 §3.3 的 20–30 min 宏循环口径混入本判定 |

### 1.3 理由（三条，逐条可复核）

1. **机制层允许 ≠ 体验层目标**。OD-2 A 的「思考时间无限」是**机制事实**：不强制推进、不设倒计时、不惩罚挂机、不申请后台权限（`docs/architecture/architecture.md` §5.2）。AC4 的 5–12 min 是 `design/concept/game-concept.md` §3.3 的**体验目标**：「通勤路上打完一个市政周期」「超出即视为节奏设计失败」。二者分属不同层，不构成实质冲突；本裁定只约束**验收计时**，不改动机制。
2. **剔除思考会让判据失效**。若把暂停态思考排除，`T_active` 可被任意玩家通过「慢想」压到 5 min 内，AC4 会退化为**永远 PASS**，失去验收意义，也无法暴露「议题太难读 / 诊断面板找不到」这类真实节奏缺陷（概念 §9.1 R4 反馈黑箱、P4 30 秒决策）。
3. **与 P4 / 30 秒决策同源**。`design/ux/ux-spec.md` §3.3 的「V1 读 5–10 s + V2 诊 10–20 s + 单个决策 10–20 s ≤ 30 s」同样是**真实经过时间**口径；AC4 是它在中循环尺度上的延伸，计时口径必须一致，否则两条判据无法互相印证。

### 1.4 判定方式：慢 / 快两类受试者

> 「思考时间无限」使慢思考者**不应被直接判 FAIL**，但也不能直接判 PASS。故设双指标 + 分类判定，把 OD-2 A 的机制自由与 AC4 的体验目标同时保住。

| 分类 | 定义（可判定） | 判定规则 |
| --- | --- | --- |
| **快类 Fast** | 单次决策（V1→V2→单个决策动词）时长 ≤ 30 s（UX §3.3），且**不存在**单段 ≥ `<T_idle>` 的静止无操作段 | `5 ≤ T_wall ≤ 12` 且 `TC-AC4-03` 事件链完整 → **PASS**；`T_wall < 5` → 先核对事件链，缺任一环节判 **FAIL**（疑似未真正走完中循环），环节齐全则记 **CONCERNS** 并说明；`T_wall > 12` → **FAIL** |
| **慢类 Slow** | 存在 ≥1 段 ≥ `<T_idle>` 的静止无操作段，或单次决策 > 30 s | `T_active ≤ 12 min` 且 `T_wall ≤ <T_slow_ceiling>` 且事件链完整 → **CONCERNS / 条件通过**（记录「节奏偏慢」并纳入观察，**不计入 PASS 样本**）；`T_active > 12 min` 或 `T_wall > <T_slow_ceiling>` → **FAIL** |
| 外部中断 | 中断段已剔除但仍影响会话连续性 | 该场次记 `INVALID`，须更换会话重测；中断段单独统计 |
| 样本级结论 | 快类 PASS 比例 + 慢类 CONCERNS 比例分别统计 | 按 `<N_playtest>` 与通过比例阈值（开放项 O-2）汇总；**慢类 CONCERNS 不得折算成 PASS**；存在任一 FAIL 且无重测通过 → AC4 判 FAIL（S2 起，命中主判据则 S1） |

> `<T_idle>` / `<T_slow_ceiling>` / `<N_playtest>` 均为**测试侧占位**，需用户 / 主理人确认（`tests/test-strategy.md` §10.2 / §13 O-2）。**该计时口径裁定本身亦为开放项 O-3，须经用户 / 主理人确认后方可用于正式判定**；本轮只交付规则，不做判定。

### 1.5 「可见进展」的可观测判据（§2 供全部用例引用）

**成立条件**：一次中循环内**至少命中 ① 或 ② 之一**，且**总命中数 ≥2 项**：

| # | 可观测事件 | 证据来源 |
| --- | --- | --- |
| ① | 一条议题的状态发生可读取变化（`NEW → ACTIVE → RESOLVING → CLOSED` 或 `CONVERTED`），状态形状图标 + 文案可读取 | 议题日志 / 截图（GDD 05 §3.3） |
| ② | 常驻三指标中 ≥1 项数值发生可读取变化（`S` / `B_t` / 周期），且 `Δ_t` 中可查到 `old / new / delta / direction` | `Δ_t` / HUD 截图 |
| ③ | L1 四因子中 ≥1 项 `f_i` 在面板中可读取变化 | L1 面板 / `Snapshot_t` |
| ④ | 流线三态（畅通 / 缓行 / 拥堵）至少一段发生可读取切换 | 流线截图 / `q_over_cap[]` |
| ⑤ | 市民之声产生 ≥1 条新文本且绑定 `cause_ref` | 文本日志（AC-I4） |
| ⑥ | 周期进度 `k/<K>` 递增（`<K>` 占位） | 周期详情 / 日志 |

**反向不成立（明确排除）**：仅出现通道 A 的即时反馈（落位 / 高亮 / 按压态 / 扣减预览 / Tab 切换）**不算可见进展**——它是 <100ms 即时反馈，不是中循环推进（ADR-004 §2 双通道）。仅「点了一次『结束本日』但无任何指标 / 议题变化」同样不算。

### 1.6 「完整中循环」的事件链定义

一条中循环 = 一个议题从**出现 → 诊断 → 处置 → 消退 / 转化**（`design/concept/game-concept.md` §3.2「中循环 3~8 min」）。须按序观测到：

```
V1 读（指标 / 议题） → V2 诊（L2 四段归因） → V3 划 / V4 拨 / V5 连（至少 1 个决策动词）
  → V6 推（≥1 次 tick） → V7 察（指标 / 议题 / 流线变化） → V8 调（回到决策动词修正）
  → 议题 CLOSED 或 CONVERTED
```

任一环节缺失 → **不是完整中循环**，`TC-AC4-03` 判 FAIL，AC4 不得判 PASS。

### 1.7 与 AC1 的 10 分钟边界如何区分（逐列对照）

| 维度 | **AC1** | **AC4** |
| --- | --- | --- |
| 判定对象 | **首个市政周期**（宏循环：`<K>` 个 tick + 周期结算 + V9 兑 / 可回退重试） | **一个完整中循环**（一条议题的出现 → 诊断 → 处置 → 消退 / 转化） |
| 会话要求 | **首次会话 / 全新存档 / 新玩家 / 无外部说明** | **任意单次会话**；可复用 AC1 同批受试者的**第二次会话**，无需全新存档 |
| 起点 `T_start` | 设备交付 + 开场话术 + 计时启动 | 主持人宣布「本段计时开始」的瞬间（新会话则同 AC1） |
| 终点 `T_end` | 「首个市政周期结算完成」结果首次出现的帧 | 议题 `CLOSED` / `CONVERTED` 且可见进展成立的首帧 |
| 时间要求 | **上限 10 min**（`≤ 10`，无下限） | **区间 5–12 min**（`≥ 5` 且 `≤ 12`）；`< 5` 须核对事件链完整性 |
| 认知判定 | **含**「理解分区—通勤—满意度因果」事后访谈（`TC-AC1-02`） | **不含**任何因果理解 / 认知判定 |
| 主线证据 | Playtest 观察表 + 访谈 + 首个周期事件链 | 会话计时原始数据 + 议题生命周期日志 + 可见进展证据 |
| 形态 | 手机竖屏（唯一 Must） | 手机竖屏（唯一 Must）；平板 / 折叠屏仅作性能测量形态 |
| 样本 | `<N_playtest>` 名「从未见过本作」受试者 | 可同一批，但须**分别起止计时、分别标注、分别判定** |
| 重叠处理 | 允许同一场会话同时采集两组时间戳，但**两组判定不得互相替代**；报告须分栏记录 | 同左 |

> 依据：`design/concept/game-concept.md` §3.2 / §3.3 / §5.2；`production/epics/epic-breakdown.md` §2.1；`tests/test-cases/AC1-onboarding.md` §1.6。

| 测试数据 | 动效开 / 关两态下各一次完整「划分区 → 结束本日 → 诊断」流程；loop 动效清单（选中呼吸 / 议题脉冲 / 拥堵脉冲 / 落位尘环 / 档位切换缓动）；静态替代资产（方向箭头 / 静态描边）截图 |
| 关联风险编号 | `CR-4`（反馈黑箱）、`MR-13`（可访问性被性能降级误删）、`AR-004-R5` |

**编号步骤**

1. 动效开：跑一次完整流程，记录两级反馈（通道 A 即时 / 通道 B tick 后）时序。
2. 动效关：跑同一流程，逐项检查 loop 动效 / 粒子 / 相机缓动是否停播。
3. 检查即时反馈在关闭态是否改为瞬时静态（描边 / 按压色 / 数值直变）且**未取消**。
4. 检查双态切换（观赏 / 决策）与 L0/L1/L2 档位切换是否瞬时、信息不丢失。
5. 检查状态变化是否 ≥2 个通道（颜色 + 形状 / 文字 / 动效），单一通道失效（去色 / 静音 / 动效关）时信息仍可达。
6. 检查开关设置可持久化、重启后状态保持、不重启即可生效。

**预期结果（可观测 / 可判定）**

- E1 动效开时两级反馈分离可观测：即时反馈在 <100ms 级（建议基线）给出，模拟结果仅在 V6 后出现；**不出现「先跳数值再落位」时序倒置**（UX E2）。
- E2 动效关后连续 3 秒画面**无任何周期性像素变化**；loop / 粒子 / 相机缓动全部停播（AC-A03-2）。
- E3 即时反馈在关闭态**改为瞬时静态、信息不丢失**，仍可完成一次完整流程（AC-A03-3 / ADR-004 A4 / AR-004-R5 反面）。
- E4 去色 / 静音 / 动效关三种单通道失效情况下，关键信息（指标值、议题状态、归因四段）仍可读取（AC-A07-2）。
- E5 开关设置可持久化、重启后保持、不重启生效（AC-A03-1）。
