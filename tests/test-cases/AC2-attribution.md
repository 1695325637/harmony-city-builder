## 1. 归因链判定模型（本用例集共用）

| 项 | 定义 |
| --- | --- |
| 显著变化 | `ΔS ≠ 0`（AC2 口径）；GDD 05 §4 的议题触发阈值 `<θ_i>` 另属平衡期占位，不混用 |
| 一条「具体原因」 | 同时具备：① `primary_factor ∈ {f_c, f_s, f_e, f_f}`；② `dS_i`（该因子贡献，分/tick）；③ `detail` 指向**具体通勤线 / 覆盖不足片区 / 预算项 / 环境源**之一，且带 `refId`；④ 可一次点按到达的 `suggested_verb`（`design/gdd/systems/05-issues-diagnosis.md` §3.1 / `design/ux/ux-spec.md` §4.3） |
| 禁止的「通用提示」 | 无 `cause_ref`、无 `refId`、无因子名、仅「城市状态有所变化」类文本（`TUTORIAL` 卡除外并须明确标注「教学」） |
| 四类归因来源 | 通勤线（03 的超时通勤线 / `q/cap` 饱和）、覆盖不足片区（03 的 `t_g` 超 `<T_s,max>`）、预算项（04 的 `I_f` / `C_m` / `I_t` / `B_t`）、环境源（02 产业格 + 03 通勤图距离产生的 `E`） |
| 只读判据 | 打开诊断面板前后 `tickId` 不变、无 P2 通勤求解调用、无 `S_t` 重算、`Snapshot` 字节不变 |
| 冷归档 | ≥3 周期，覆盖 D4「负面后果在 2~3 个周期后浮现」（`design/concept/game-concept.md` §2.2 D4；`docs/architecture/architecture.md` §4.3） |

- E5 同输入重复结算的归因链条目数、`refId`、`contribution` 完全一致（确定性，AC-F4 / AC-T4）。

### TC-AC2-05 · 跨 2~3 周期滞后暴露（D4）仍可查完整归因链

| 字段 | 内容 |
| --- | --- |
| 用例 ID | `TC-AC2-05` |
| 覆盖 | **AC2**；DoD D-1 / D-2；Story S-05 / S-09 / S-12；GDD **AC-I5** / **AC-I6** / **AC-F2**；`design/concept/game-concept.md` §2.2 **D4**；ADR-002 §7 **A5**；ADR-003 §8 **A5**；`production/epics/epic-breakdown.md` §4 S-05 验收 4 |
| 优先级 | **P0** |
| 类型 | 自动（跨周期回放 + 冷归档查询） |
| 前置条件 | S-05 已交付；冷归档 ≥3 周期；配置表 `<K>` 已注入（占位）；`configHash` / `schemaVersion` / `engineVersion` 全程固定 |
| 测试数据 | 周期 1 埋入一处分区 / 路网决策；连续推进 2~3 个完整周期（共 `2×<K>` ~ `3×<K>` 个 tick）；每 tick 的 `TickSnapshot` + `Δ_t` + 归因链落盘 |
| 关联风险编号 | `MR-09`（冷归档不足 / D4 无法复盘）、`MR-14`（归档体积超估算）、`CR-4`、`AR-003-R3` / `AR-003-R7` |

**编号步骤**

1. 周期 1 提交一处会导致后续恶化的决策（占位构造，不填数值），记录该 tick 的 `tickId` 与命令溯源。
2. 连续推进 2~3 个完整周期，逐 tick 保存 `TickSnapshot` / `Δ_t` / 归因链。
3. 在周期 3 出现 `ΔS ≠ 0` 时，从诊断面板查询「2~3 周期前」那次变化的完整归因链。
4. 反查该归因链的 `t-1` / `t` 双帧、因子贡献分解、通勤线明细与命令溯源。
5. 进程重启后从存档载入冷归档，重复步骤 3。
6. 检查冷归档实际保留周期数与常驻 / 归档体积实测值。

**预期结果（可观测 / 可判定）**

- E1 周期 3 的变化可追溯到 ≥1 条具体原因，且该原因能沿归因链回指到周期 1 的决策与具体通勤线 / 片区 / 预算项（D4 滞后暴露可复盘）。
- E2 冷归档**保留 ≥3 周期**，被查 tick 的 `t-1` / `t` 双帧、`dS_by_factor[4]`、通勤线明细、命令溯源字段全部可读且不为空（ADR-002 A5 / S-05 验收 4）。
- E3 重启载入后查询结果与重启前逐字节一致；`configHash` / `schemaVersion` / `engineVersion` 全程未变。
- E4 议题按 `<k>` 静默 tick 观察窗处理，不出现「刚要复盘就自行消失」（GDD 05 E4 / AC-I5）。
- E5 常驻内存 / 归档体积仅记录**实测值**并与 `docs/architecture/architecture.md` §4.3 的估算量级比对，**不预先冻结为硬指标**（建议基线口径）。
