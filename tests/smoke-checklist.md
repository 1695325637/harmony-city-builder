## 0. 通用执行规则（先读）

1. **失败即停**：任一冒烟项命中「失败即停规则」→ **该波次出口门判 FAIL**，立即停止该波次剩余检查、锁定现场证据（截图 / 日志 / 快照 / 帧录制）、按 `tests/test-strategy.md` §6 开缺陷单，**不得进入下一波次**。FAIL 即「未达 QA」；质量门为 advisory，最终是否放行由用户决定。
2. **执行顺序**：按 W0 → W1 → W2 → W3 → W4 → W5 顺序；每波次内按编号顺序执行。
3. **前置**：W0 须先通过 `tests/test-strategy.md` §5.1 准入门 A-1~A-7（上游版本锁定、用例齐备评审 ADEQUATE、占位符口径、构建锁与机型矩阵、Playtest 招募方案、测试侧占位确认、H1~H3 未排期）。
4. **证据**：每条冒烟项须留至少 1 份可溯源证据，路径规范见 `tests/test-strategy.md` §7.1；无证据的结果判 `INCOMPLETE`，不计入 PASS。
5. **建议基线纪律**：涉及 30fps / DrawCall / 内存 / 首包 / <100ms / 结算 p95 ≤16ms 的项目，**只记录实测值与达标率 % 并与建议基线比对**；**不得因数值超出建议基线而判 FAIL**，也不得把建议基线写成已承诺硬指标（`docs/architecture/architecture.md` §10.1 / `docs/architecture/control-manifest.md` §1.8）。
6. **切片边界**：任何冒烟项不得包含公共交通 / 政策卡 / 地价 / 多道路等级 / 独立危机事件 / 跨设备 / 折叠屏双栏 / 季节昼夜 / 成就 / 分享 / ×1×2×4 自动播放 / 具象个体市民 / 无尽地图 / 付费加速；折叠展开态与平板**仅作性能测量形态与降级路径验证**（`tests/test-strategy.md` §4.2 / §11）。
7. **本轮诚实性**：**32 条冒烟项全部未执行**；下表「结果」列一律留空，不得预填 PASS。本清单只交付「最小可跑集合 + 失败即停规则」。
