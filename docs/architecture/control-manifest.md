## 0. 使用方式与立场

- **§1 是控制清单本体**：一页、祈使句、可勾选。任何 Story 开工前先读它，代码评审逐条对照，命中「禁止」列即退回。
- **§2 是风险登记**：本轮**不消除**风险，只钉「谁盯、看什么信号、怎么验」。主理人点名的 5 项（预览版 API、ASTC/ETC2 与合批、包体上限、字体授权、真机 profiling）已全部登记为 R-01~R-05。
- **§3 是评审门自检**：`architecture.md` §13 的 G1~G12 结论抄录于此，供汇编与后续评审直接引用。
- **硬立场**：美术圣经 §9.4 与本文所有性能数字均为**建议基线 / 非承诺值**（T-107 CONCERNS ① 立场保持）；平台特性一律「须真机验证后方可排期」；跨专业冲突只登记、不擅改 `design/` 上游文档（**X-1~X-5 已裁定关闭（设计评审门 2026-11-05），见 §4**）；**G11 已回执：不补引擎参考文档，K-1~K-5 走 §5.1 回填机制**。

## 1. 一页控制规则（Control Rules · 可立即执行）

> 图例：**✅ 必须做** / **⛔ 禁止做** / **🔎 每次提交自检**。括号内为对应主文档章节或 ADR。

### 1.1 平台与工程链路（ADR-001）

| # | 规则 |
| --- | --- |
| ✅ | 游戏规则、场景、图集、配置表**只在 Cocos 工程侧**维护；HarmonyOS 工程骨架视为构建产物 + 极薄胶水（§1.2） |
| ⛔ | **禁止在 ArkTS 层写任何游戏规则**；禁止业务层 `import` 任何 HarmonyOS SDK / ArkTS 模块（§1.3 / G2） |
| ✅ | 系统能力一律经 `PlatformAdapter` 的六个接口：`ILifecycle` / `IWindowInsetProvider` / `IFoldStateProvider` / `ISaveStorage` / `IAccessibilityBridge` / `IFeatureFlags`（§2.3） |
| ✅ | HUD / 议题 / 诊断面板全部在 Cocos 场景树内绘制；ArkUI 只承载宿主容器与（H1 若做）卡片（§1.3） |
| ✅ | Cocos 小版本 / HarmonyOS SDK·API / DevEco Studio 三者写入构建锁；升级强制重跑 §10.3 校准（§1.2 纪律 2） |
| 🔎 | 每次提交检查：业务层 import 白名单为空？适配层是否膨胀成「什么都能调」的后门？ |

### 1.2 模拟层（ADR-002）

| # | 规则 |
| --- | --- |
| ✅ | `S_{t+1} = F(S_t, commands, config)` 写成**纯函数**；默认暂停，tick **仅**由 V6「结束本日」触发（§3.1） |
| ✅ | 结算按 **P0→P8 固定顺序**；P2→P3→P4 因果链不可交换；P3 复用 P2 通勤图（§3.2） |
| ⛔ | 禁止墙上时钟、`Math.random()`、依赖 Map/Set 遍历顺序、浮点累加顺序漂移；随机一律用**可种子化 PRNG，种子入快照**（§3.3） |
| ⛔ | 禁止热路径分配（每 tick GC）、禁止模拟层调渲染 / 平台 API、禁止在渲染帧里推进模拟（§2.2 / §3.1） |
| ✅ | 满意度 4 因子公式 / 权重**只从配置表注入**，代码里不硬编码；配置变更须升 `configHash`（§0.2） |
| ✅ | 每个显著指标变化由 `AttributionRecorder` **在结算时**记 ≥1 条归因；诊断面板查询时**只读**（§4.2 / ADR-003） |
| 🔎 | 每次提交跑确定性回放断言：同一 (S_t, 命令, 配置) 两次结算须**逐字节一致**（ADR-002 A1） |

### 1.3 数据 / 快照 / 存档（ADR-002 + ADR-003）

| # | 规则 |
| --- | --- |
| ✅ | 快照**自包含**：`tickId` / `schemaVersion` / `configHash` / `engineVersion` / PRNG seed / 命令溯源缺一不可（§4.1） |
| ✅ | 保留策略 Keyframe（周期首 / 末全量）+ Delta（周期内差分与归因）+ 冷归档 **≥3 周期**（覆盖 D4）（§4.3） |
| ✅ | 回退 / 撤销 = **恢复 Keyframe + 丢弃其后 Delta**；`tickId` 单调递增不复用（§4.3 / ADR-003） |
| ⛔ | **禁止写任何「逆运算」撤销**；禁止各模块自行相减指标或重算归因（用同一份 Δ_t / 归因链） |
| ✅ | 落盘用临时文件 + fsync + rename 或 A/B 双槽；加载失败回退上一完好槽（§5.3） |
| ✅ | 版本不匹配走**显式迁移器**或拒绝载入并保留旧槽；⛔ 禁止静默用新公式续算旧档（§5.3） |
| ⛔ | 存档**不记录参与模拟计算的墙上时钟**；不申请后台保活 / 精确闹钟 / 离线任务权限（§5.2 / ADR-003） |
| 🔎 | 每次提交自检：checksum、版本头、故障注入用例是否仍在；口径上不得把 checksum 说成「反作弊」 |

### 1.4 UI 与反馈（ADR-004）

| # | 规则 |
| --- | --- |
| ✅ | **双通道**：即时反馈（渲染帧内、<100ms、视觉）与模拟结果（Δ_t / 事件、跟随 tick）彻底分离（§7.1） |
| ⛔ | **禁止把 UI 反馈绑到 tick**；禁止 UI 写网格 / 写预算 / 写满意度；⛔ 禁止维护双份权威状态（§2.2 / §7.2） |
| ✅ | UI 只持有 VM（快照只读投影 + 本地乐观叠加）；非法命令用 `BudgetRejected` 撤下乐观视图并给形状编码负向反馈（§7.2） |
| ✅ | 结算期间 InputGate 锁「推 / 改状态」，但**纯视觉反馈仍响应**（§7.3 / ADR-002） |
| ✅ | 「减少动态效果」下即时反馈**改为瞬时静态、不取消**（§7.4）；倍速只是「定时产生 V6 命令」，分层不变、flag 默认关 |
| 🔎 | 每次提交自检：手机竖屏 / 折叠展开 / 平板三形态下反馈与热区一致；<100ms 计时断言在 CI |

### 1.5 渲染 / 资源（美术圣经 §9.3 / §9.4）

| # | 规则 |
| --- | --- |
| ✅ | UI / UI-图案 / 地形 / 道路常驻；建筑按**激活分区集**按需加载；VFX / 天气按 LOD 与性能档位加载（§6.1） |
| ✅ | LOD 三档打入**同一图集**、UI 图标全入 UI 图集、面板一律 9-slice（§6.1 / 美术圣经 §2.3） |
| ⛔ | 禁止逐对象独立材质 / Shader 变体；禁止渲染层回写状态；禁止贴图内硬编码色值（§6.1 / §9.1） |
| ✅ | 纹理格式走**能力探测**：ASTC → ETC2 → RGB565 降级；探测结果写入校准记录，不写死在资源里（§6.3） |
| ✅ | 分区类型做**可扩展枚举 + 配置表**；图集分包 / 分类 Tab / 图案表由配置生成，不写死数量（§6.4，化解冲突 X-2） |
| 🔎 | 每次提交自检：同图集 + 同材质 + 相邻 UI 层级是否被打断；常驻纹理水位是否超基线 |

### 1.6 可访问性（美术圣经 §9.2，Standard 起步）

| # | 规则 |
| --- | --- |
| ✅ | 分区 = 色 + 图案 + 文字**三编码**；状态 = 色 + 形状（✓/!/✕/锁/↑↓）；全部经 `SemanticTokenMap` 单一映射（§9.1） |
| ✅ | 文本缩放 100–200% 弹性容器不截断；热区 ≥44dp、间距 ≥8dp；长按 / 拖拽有点击替代；状态变化 ≥2 通道（§9.2） |
| ⛔ | **禁止以性能为由降级任何 §9.2 项**（语义令牌 / 图案层 / 形状编码 / 热区 / 缩放 / 静态校验）（§9.3 / 美术圣经 D-8） |
| ✅ | 优先系统字体引用；内嵌字体先过法务授权确认（§9.2 / R-04） |
| 🔎 | 每次提交跑色板对比度（正文 ≥4.5:1、大字 / 边界 ≥3:1）与去色 / 三型色盲模拟静态校验 |

### 1.7 平台特性与范围纪律（硬约束）

| # | 规则 |
| --- | --- |
| ⛔ | **H1 秒启卡片 / H2 折叠双栏 / H3 跨设备流转一律不进 Must**；H4 分布式多机同局 **Won't**、不预留不评估（§8.4） |
| ✅ | 任何平台特性在文档 / 代码 / 对外口径中须带「**须真机验证后方可排期**」标注（§8.4） |
| ✅ | 折叠 / 安全区接口不稳时走降级：启发式宽高比判形态 → 读不到 insets 用「固定上下分栏 + 手动留白 24dp」→ 整体安全容器内缩 → 纯 UI 重排（§8.3） |
| ⛔ | 禁止形态切换重建场景 / 重置模拟状态 / 丢失选中态；禁止把 H3 同步逻辑写进首版（§8.2 / §5.4） |
| ✅ | 「功能不降级，只降信息密度增益」：任一形态 V1–V9 完整可达（§8.2） |
| 🔎 | 每次提交自检：feature flag 默认全关？平台特性是否误入 Must？ |

### 1.8 性能与校准（§10）

| # | 规则 |
| --- | --- |
| ⛔ | **禁止把 §9.4 建议基线当作已承诺硬指标**对外 / 对内使用（§10.1） |
| ✅ | 用固定「基准城市」（32×32 满网格 / L1 / 含拥堵 + 3 议题）测，测 p50 / p95 而非平均值（§10.3 步 1/3） |
| ✅ | 五步：定基准场景 → 定机型矩阵（低 / 中 / 高 × 竖屏 / 折叠展开 / 平板）→ 采集 → 逐条比对冻结或降级 → 纳入 CI 回归（§10.3） |
| ✅ | 降级顺序：天气粒子 → 夜间窗光 / AO → VFX 粒子 → 更早进 L0 → 低档关全部 VFX；**不降可访问性与 <100ms 反馈**（§10.4） |
| 🔎 | 引擎 / SDK 升级后强制重跑校准；校准报告回写 `architecture.md` §10.1 |
