## 1. 背景（Context）

美术圣经 §6.6 给出一条**跨专业硬约束**：

> 「UI 操作反馈不受模拟 tick 约束：放置、拆除、切 Tab、选中、倍速等必须在 **< 100ms** 内给出视觉响应；只有模拟结果（资金变化、满意度、交通状态）才跟随低频 tick 更新。若把 UI 反馈也绑到 tick，玩家会感到『点了没反应』。」附录 D-3 把它列为「程基岩 / team-lead 需确认实现分层」的未决项。

概念侧同向加压：§7 锚点 8 要求「每个玩家动作有**两级反馈**——即时可见（落位 / 高亮 / 扣减动画）+ tick 后可见（指标变化 / 议题）」；§9.1 R4 把「点了没反应」列为会摧毁胜任感的**反馈黑箱**风险；OD-2 A 又规定默认暂停、手动推进 tick（ADR-002），意味着「下一次 tick 可能几分钟后才发生」。

于是出现一个必须回答的矛盾：**既要 <100ms 即时反馈，又不能让 UI 抢改权威状态**（否则破坏 ADR-002 的确定性、回退与 AC2 归因）。此外还需同时满足：
- 美术圣经 §9.2：动效可关（减少动态效果）、文本缩放、≥44dp 热区、多通道反馈在**同一套 UI 栈**里一致生效；
- 概念 §3.3 / §1.3：同屏 ≤3 全局指标、3±1 议题，UI 分层而非加面板；
- ADR-001：游戏 UI 全在 Cocos 场景树内，只有一套动效策略与安全区策略。

**知识缺口声明**：真机上「点按 → 首帧可见反馈」的实测分布未知（主文档 §10.1 把它列为架构补充测量项），本 ADR 只钉分层与口径，<100ms 为**建议基线性质的验收目标**，须真机测量达标率后转硬指标。

---

## 2. 决策（Decision）

> **采用「双通道 + 乐观视图 + VM」：通道 A（即时反馈）在渲染帧内由 UI 本地同步产生视觉响应，<100ms、与 tick 完全无关；通道 B（模拟结果）仅在 V6 触发后由 Δ_t / 归因链 / 事件驱动更新。UI 只持有「视图模型 VM = 快照只读投影 + 本地乐观叠加」，绝不持有或修改权威游戏状态；非法命令由结算事件回滚乐观视图。**

六条子决策：

1. **双通道彻底分离**：
   ```
   通道 A · 即时反馈（同步、帧内，<100ms，不受 tick 约束）
     玩家操作 → UI 本地生成乐观视图（落位高亮 / 按压态 / 扣减动画 / Tab 切换 / 选中描边）
              → 同帧或下一帧渲染
              → 同时把操作包装为 Command 投入 pending queue（ADR-002 P0/P1）

   通道 B · 模拟结果（事件驱动，仅 V6「结束本日」触发）
     TickPipeline 结算 → Δ_t / 归因链 / 事件广播
              → UI 按 Δ 做指标滚动、议题出现/消退；渲染层播世界状态动效（可关闭）
   ```
   放置 / 拆除 / 切 Tab / 选中 / 倍速（若开启）走 A；资金 / 满意度 / 交通状态走 B。**两级反馈（概念锚点 8）即两通道的可观测表现**。

2. **UI 不持有权威状态**：VM 是只读投影 + 视觉叠加。权威值永远以 ADR-002 P8 的 Δ_t 为准；UI 不得写网格 / 写预算 / 写满意度（主文档 §2.2 编码标准、评审门 G3）。

3. **乐观视图可回滚**：命令在 P1 被判非法（如预算透支、地块不可用）→ 广播 `BudgetRejected` → UI 撤下乐观视图并给负向反馈（形状编码 ✕，语义令牌 §9.1）。既保证 <100ms，又不显示错误数值。

4. **输入闸门协作**：结算期间（P0 锁 → P8 解）由 InputGate 显示「结算中」态并拒重复点按（ADR-002 R-2）；结算耗时须短到玩家无感（建议 p95 ≤16ms，主文档 §10.1）。两通道互不阻塞：结算不卡渲染帧、渲染帧不触发模拟。

5. **倍速不改变分层**：×1×2×4 自动播放（Should，不进首版 Must，概念 OD-2 A）本质是「按间隔自动产生 V6 命令」，仍走通道 A 反馈 + 通道 B 结算，只是命令来源从手动变定时器；`IFeatureFlags` 默认关。

6. **动效 / 可访问性统一策略**：`MotionPolicy` 全局开关。开启「减少动态效果」时 loop 动效 / 粒子 / 相机缓动停播、昼夜 / 缩放瞬时切换；**即时 UI 反馈不取消，改为瞬时静态反馈**（描边 / 色块 / 数值直变），保证信息传达不丢失、仍 <100ms。语义令牌（色 + 图案 + 形状 + 文字）、文本缩放 100–200%、≥44dp 热区、点击替代路径由同一套 UI 栈提供，**不因形态切换（折叠 / 平板）产生第二套策略**（ADR-001 / 主文档 §8）。

## 3. 备选方案（Alternatives）

| # | 备选 | 描述 | 为何未选 |
| --- | --- | --- | --- |
| A1 | **UI 反馈绑定 tick**（每次操作后等下一次结算才显示） | 实现最简单、状态绝对一致 | **正是美术圣经 D-3 点名要否决的做法**：OD-2 A 下一次 tick 可能几分钟后，玩家「点了没反应」，命中概念 R4 反馈黑箱、破坏 AC1 / AC4 |
| A2 | **UI 直接改权威状态**（点了就写网格 / 扣预算，不等 tick） | 反馈快、初看很自然 | 破坏 ADR-002 确定性纯函数与命令溯源：回退 / 回放 / 归因链全部失真；非法操作无法回滚；UI 与模拟两处写状态必然不一致 |
| A3 | **双份状态各自为政**（UI 一套、模拟一套，靠同步对齐） | 各自独立、看似解耦 | 同步逻辑复杂度爆炸，Δ_t / 归因 / 存档出现两个真源；与 ADR-003「一份数据多处复用」直接冲突 |
| A4 | **每次操作即时跑一次迷你模拟** | 想让「即时反馈」也带真实数值 | 违反 OD-2 A「tick 之间状态冻结」；通勤求解被高频触发，性能与确定性双输；混淆两级反馈语义 |
| A5 | **游戏 UI 用 ArkUI、世界用 XComponent**（两套栈分别做反馈） | 原生 UI 反馈天然快 | ADR-001 A5 已否决：两套安全区 / 两套文本缩放 / 两套动效策略 / 两套状态，可访问性与 <100ms 一致性无法保证 |
| A6 | **「减少动态效果」时连即时反馈一起关掉** | 实现最省 | 直接违反美术圣经 §9.2「开启后信息不丢失」与概念锚点 8 两级反馈；信息传达被切断 |
| A7 | **把 <100ms 直接写成已承诺硬指标** | 省去真机校准 | 主理人硬约束：§9.4 性能数字均为建议基线，须给「转硬指标」实测方案，不得照抄为已定指标；本 ADR 只钉分层，达标率待真机测量 |

## 4. 理由（Rationale）

1. **正面回答美术圣经 D-3**：把「即时反馈 vs 低频 tick」从「要不要等」的取舍，变成「两条独立通道」的结构问题；两者不再竞争同一时钟。
2. **同时满足快与对**：<100ms 由本地视觉保证（不依赖模拟），数值正确性由 P8 的 Δ_t 与 `BudgetRejected` 回滚保证，二者不矛盾。
3. **保护 ADR-002 / ADR-003 的基石**：UI 零写状态 → 确定性、命令溯源、Keyframe 回退、归因只读全部成立，不被「为了快」的捷径破坏。
4. **概念锚点 8 / R4 / AC2 一并落地**：两级反馈可观测；诊断面板从 Δ + 归因链读数据（ADR-003），不重算、不卡顿。
5. **可访问性一致性**：单一 UI 栈 + MotionPolicy + 语义令牌，使折叠 / 平板 / 减少动态效果 / 文本缩放等形态变化只影响布局，不产生「某形态下反馈丢失」的分支（主文档 §8.2 回退原则「功能不降级」）。
6. **Should 特性零侵入**：倍速只是命令来源变化，分层不变；首版 feature flag 默认关，符合 OD-2 A「不进 Must」。

## 5. 后果（Consequences）

**正面**
- 玩家感知与模拟正确性解耦：帧率波动、结算耗时、暂停时长都不影响「点了有反应」。
- UI 层可独立做交互回归 / 截图回归；模拟层保持纯函数可单测（ADR-002）。
- 非法操作有明确回滚路径，预算 / 地块规则仍由模拟层单点裁决。
- 折叠 / 平板 / 减少动态效果 / 文本缩放共用一套反馈与动效策略，降低可访问性回归面。

**负面 / 成本**
- 需要维护「乐观视图 ↔ 权威值」的对齐与回滚逻辑（比「点了就写」复杂）。
- 通道 A 的视觉反馈**不能显示未经裁决的真实数值**（否则会与 Δ_t 冲突），需在 UX 上约定「即时只给落位 / 按压 / 高亮，数值变化走通道 B」——这是与 UX 规格（`design/ux/ux-spec.md`）的对接点，须在一致性对齐时确认。
- `BudgetRejected` 回滚若延迟过高，会出现「先亮起又被撤下」的闪烁，需把 P1 校验前置提示（可用性预检）与即时反馈配合。
- <100ms 达标率需真机测量（多形态 / 低档位机），不能靠设计断言。

**中性 / 边界**
- 本 ADR 不定义具体动效时长 / 缓动曲线（美术圣经 §8.2 已定），只定义「谁受 MotionPolicy 管、受 tick 约束与否」。
- 不定义 HUD 具体控件与指标项数（归 UX 规格 + 概念 §3.3 硬上限；跨专业冲突 **X-1 / X-3 已由设计评审门裁定关闭（2026-11-05），见 `architecture.md` §12.1 裁定记录表**）。
- 倍速控件档位争议（X-1）**已由设计评审门裁定关闭（2026-11-05），见 `architecture.md` §12.1 裁定记录表**；本 ADR 只保证「无论开不开，分层不变」，`IFeatureFlags` 默认关保留为 Should 期能力位。

## 7. 验收（Acceptance）

| # | 验收条件 | 证据路径（后续实现阶段产出） |
| --- | --- | --- |
| A1 | 放置 / 拆除 / 切 Tab / 选中 /（若开启）倍速在**默认暂停且未发生任何 tick** 时，均于 <100ms 内给出可见视觉响应；真机测达标率并记录（作为校准输入，不预先冻结） | S-07 反馈计时记录 + S-12 校准报告 |

| A3 | 即时反馈与 tick 结果两级可观测：连点两次「结束本日」不产生两次结算（InputGate），结算期间纯视觉反馈仍响应 | S-03 / S-07 输入闸门联验 |
