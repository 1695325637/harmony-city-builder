## 1. 背景（Context）

用户拍板 **OD-2 A 主动推进制**：默认暂停，玩家点「结束本日」结算一次 tick，思考时间无限；×1×2×4 自动播放为 Should 期可选、不进首版 Must。同时拍板 **OD-1 A**（满意度唯一计分板、无硬终局、未达标**可回退重试**）与 **OD-4 A**（固定有限网格、按里程碑解锁新区）。

概念 §9.2 把三项技术问题明确交给架构：

1. OD-2 A 对模拟循环 / 存档 / 后台权限的约束（第 1 项）。
2. 有限网格规模上限（24×24~32×32）与通勤图求解的性能预算（第 2 项）。
3. 「诊断面板」V2 诊 所需的 tick 间指标差分与归因链的**状态快照策略**，含**回退重试如何复用快照**（第 5 项）。

另有三条硬约束需同时满足：
- 概念 §5.2「七条规则（R1~R7）全部贯通、不允许先做半套」、V2 诊不可省、AC2「任一满意度变化可追溯到至少一条具体原因」。
- 概念 D4「负面后果在 2~3 个周期后才浮现」→ 诊断与回退必须能**跨 ≥3 周期**回溯。
- 美术圣经 §6.6 / D-3：UI 即时反馈 <100ms、不受 tick 约束（由 ADR-004 承接，本 ADR 必须为其留出空间）。

**知识缺口声明**：满意度 4 因子的公式 / 权重 / 数值由系统 GDD 定义（概念 §2.1 R6 明确不越界定稿），本 ADR **不定义公式**，只钉「可注入接口 + 配置版本 hash」。通勤求解耗时为**估算**，须真机实测（主文档 §10.2）。

## 2. 决策（Decision）

> **模拟不是循环，而是「事件驱动的一次性确定性原子事务」：`S_{t+1} = F(S_t, commands, config)`；每个 tick 提交一份自包含快照 + 逐指标差分 Δ_t + 结算时记录的归因链；快照采用 Keyframe（周期全量锚点）+ Delta（周期内增量）+ ≥3 周期冷归档；回退重试 = 把权威状态恢复到目标 Keyframe 并丢弃其后 Delta，不做任何逆运算。**

六条子决策：

1. **双循环解耦**：渲染帧循环（每帧只做输入采集 / 即时反馈 / 世界动效插值 / 渲染）与 tick 结算彻底分离；tick 仅由 V6「结束本日」触发，默认暂停、思考无限、状态冻结。模拟**不依赖帧率、不依赖墙上时钟**。
2. **确定性纯函数**：`F` 禁止墙上时钟、`Math.random()`（改可种子化 PRNG，种子入快照）、依赖 Map/Set 遍历顺序、浮点累加顺序跨平台漂移；同一输入重放须**逐字节一致**。模拟层零平台依赖、零渲染依赖、**零热路径分配**（`architecture.md` §2.2）。
3. **结算 pipeline 固定顺序 P0→P8**：冻结输入 → 应用命令 → 通勤图求解 → 服务覆盖 → 4 因子满意度合成 → 经济结算 → 议题 / 市民之声 → 周期判定 → 提交。P2→P3→P4 是因果链，顺序不可交换；P3 复用 P2 的通勤图，**禁止另起半径计算**（概念 P3 否决项）。
4. **归因在结算时记录**：`AttributionRecorder` 由 P2~P5 顺带写入「指标变化 → 具体通勤线 / 覆盖不足片区 / 预算项 / 环境源」；诊断面板**查询时只读、不重算模拟**。
5. **快照三件套**：`TickSnapshot`（自包含）+ `Δ_t` + `AttributionChain_t`，由 UI / 诊断 / 存档 / 回退**共用同一份**，禁止各模块自行相减或重算。
6. **Keyframe + Delta 保留策略**：周期内每 tick 存 Delta（差分 + 归因 + 命令溯源，不含逐格全量）；周期首 / 末存 Keyframe（全量）；冷归档保留 ≥3 周期（覆盖 D4）。热窗口常驻最近 K = 一个周期 tick 数（建议 24，由 GDD 钉定）。

**规模钉定（架构建议，交主理人确认后写入 GDD）**：逻辑网格固定 **32×32 = 1024 格为 MVP 硬上限**，16×16 = 256 格起步按里程碑解锁；24×24 = 576 为概念建议下界；扩到 >32×32 须重做通勤求解基准与快照体积评估。

## 3. 备选方案（Alternatives）

| # | 备选 | 描述 | 为何未选 |
| --- | --- | --- | --- |
| A1 | **每帧增量模拟**（把低频 tick 做成每帧累加小步长） | 渲染帧循环里推进模拟 | **违背 OD-2 A**（默认暂停、思考无限、状态冻结）；帧率波动会影响模拟结果，确定性无法保证；与「点按结算一次」的心智模型不符 |
| A2 | **现实时间制 / 离线推进**（OD-2 C） | tick 自动流动、离线也推进 | 已被用户否决（OD-2 A 拍板）；需后台权限 + 离线补算 + 时间基准 + 防篡改时钟，与 Pastime 美学冲突；本 ADR 无权复议 |
| A3 | **只存当前状态 + 撤销用逆运算** | 不保留历史快照，回退时反向计算每步 | 通勤流量分配、满意度合成、经济滞后回路**不可逆**（多对一映射）；逆运算既写不出也不精确；且无法支撑 V2 诊断与 D4 跨周期回溯 |
| A4 | **纯事件溯源（只存命令日志，不存快照）** | 每次诊断 / 回退从初始状态重放全部命令 | 重放几百个 tick 会让点开诊断面板卡顿（违反 <100ms 精神）；配置版本一变，用新公式重放旧命令得到不同结论，AC2「可追溯」失真；存档体积与启动时间不可控 |
| A5 | **诊断时重算归因**（不在结算记录） | V2 面板打开时重跑通勤求解来解释「为什么降了」 | 同上：卡顿 + 配置漂移失真 + 违反即时性；且把模拟逻辑渗进 UI 层 |
| A6 | **逐格 OD 通勤矩阵**（每格当通勤源汇） | 1024×1024 起讫矩阵、更细粒度 | 概念 Won't「逐车个体仿真」；1024² 矩阵 + 全源最短路在移动端浪费预算，且分区价值本就是「块」级（概念 R2 玩家不逐栋摆楼）。改用**合并分区块 B≤64** |
| A7 | **每 tick 全量快照**（不做 Keyframe/Delta） | 简单、回退直接 | 100–300 KB/份 × 数十 tick × 3 周期 → 常驻内存与存档显著膨胀（§4.3 估算）；Delta 已足够支撑诊断与回退，全量属浪费 |
| A8 | **快照不自包含**（省去 configHash / seed / engineVersion） | 依赖「当前运行环境」续算 | 配置 / 公式 / 引擎一改，旧快照算出不同结果，回退与回放失真；未来 H3 迁移也失去版本基准 |

## 4. 理由（Rationale）

1. **OD-2 A 的最轻实现**：把模拟从「循环」降为「一次性事务」，直接消除后台权限、离线结算、时间同步、时钟基准等整块复杂度（概念 9.2 第 1 项结论）。
2. **OD-1 A 的回退几乎免费**：确定性 + 命令溯源 + 自包含快照，使「未达标可回退重试」退化为「恢复一个 Keyframe」，无需写任何逆运算，也无「失败终局」分支（P7 只标记可回退）。
3. **AC2 的数据可得性**：归因在结算时顺带记录，诊断面板只读；既满足「任一满意度变化可追溯 ≥1 条原因」，又与 ADR-004 的 <100ms 即时反馈不冲突。
4. **D4 滞后暴露**：Keyframe（周期首 / 末）+ Delta + ≥3 周期冷归档，让「2~3 周期后才浮现」的后果仍有完整归因链可查。
5. **性能结论**：合并分区块后通勤求解 O(B×E) 随 N 线性（V≤1024、E≈4V≤4096、B≤64，多源 BFS ≈3.3×10⁵、含拥堵迭代 ≈10⁷ 量级基本操作），且是**玩家主动触发的一次性结算**，不是瓶颈；瓶颈在渲染 / DrawCall / 内存（主文档 §10.2）。
6. **可测性**：`F` 是纯函数 → 黄金路径单测 + 确定性回放 + 离线重放全部可行，是「验证驱动开发」的最佳落点。

## 5. 后果（Consequences）

**正面**
- 模拟层完全可单测、可回放、可离线调试；任一 tick 可重放定位问题（「可调试」编码标准）。
- 回退 / 撤销 / 周期重试共用同一机制，代码量极小；OD-1 A「无硬终局」自然成立。
- V2 诊断、AC2 验收、D4 跨周期回溯、未来快照迁移共享同一份数据，无重复实现。
- 存档只需「当前快照 + 冷归档」，无需后台与时钟（ADR-003 的直接前提）。

**负面 / 成本**
- 确定性要求严苛：禁止不可控随机 / 遍历顺序依赖 / 浮点累加漂移，规则实现需自律与 code review。
- 快照需自包含（版本 / hash / seed / 命令溯源），schema 设计比「存个状态对象」复杂。
- Keyframe/Delta 有「重放前序 Delta 以定位非锚点 tick」的额外逻辑（tick 级撤销时）。
- 每个结算阶段要写归因中间量，pipeline 实现比「直接算个结果」略重，但换来 AC2 与可调试性。

**中性 / 边界**
- 满意度公式、因子权重、建筑表、周期 tick 数全部留给 GDD；本 ADR 只钉接口与配置版本 hash，不越界（概念 §0.3）。
- 网格上限 32×32 是**架构建议**，须主理人确认后写入 GDD；本 ADR 不改任何 `design/` 文档。
- ×1×2×4 倍速（Should）只是「定时产生 V6 命令」，不改变本 ADR 的分层（ADR-004 §7.3）。

| --- | --- | --- | --- | --- | --- | --- |
| R-1 | 确定性被破坏 | 同一 (S_t, 命令, 配置) 两次结算结果不一致、回放字节不同 | 回退失真、AC2 归因失真、存档不可复现 | 禁用墙上时钟 / 原生随机 / 遍历顺序依赖；PRNG 种子入快照；关键求和定点或受控顺序；黄金路径回放断言 | 模拟 / 架构 | 确定性回放单测（S-03） |
| R-2 | 结算中重复点按 / 暂停排队导致半状态 | 连续点「结束本日」出现两次结算、pending 命令半应用 | 状态错乱 | P0 InputGate 锁队列 + 幂等键去重；P8 解锁；非法命令 `BudgetRejected` 触发 UI 回滚（ADR-004） | 模拟 / UI | 输入闸门单测（S-05 / S-07） |

| R-4 | 通勤求解耗时超预算（估算未实测） | 32×32 满网格单次结算 p95 > 16ms、点按后卡顿 | 违反 <100ms 链路、影响心流 | 合并分区块（禁逐格 OD）、P3 复用 P2 结果、零热路径分配；真机校准（§10.3）后转硬指标，不照抄估算 | 模拟 / 架构 / 性能 | 结算耗时基准（S-04 / S-12） |
| R-5 | 快照膨胀 / 内存水位失控 | 冷归档体积远超估算、低档机内存告警 | 与 §9.4 内存基线冲突 | Keyframe+Delta 混合；逐格全量只在周期锚点；冷归档落盘按需读入；≥3 周期之外按策略裁剪（保留归因摘要） | 数据 / 架构 | 快照体积 / 内存实测（S-12） |

| R-7 | 回退后 tickId 冲突 / 归因链断裂 | 回退重试后新分支与旧分支 id 重复、旧 delta 被误读 | 复盘数据混乱 | tickId 单调递增不复用；回退后新分支用新 id，旧分支 Delta 归档保留供复盘 | 数据 | 回退一致性单测（S-11） |

## 7. 验收（Acceptance）

| # | 验收条件 | 证据路径（后续实现阶段产出） |
| --- | --- | --- |
| A1 | `S_{t+1} = F(S_t, commands, config)` 为纯函数：同一输入连续结算 / 跨会话回放结果**逐字节一致** | S-03 确定性回放单测记录 |

| A3 | P0~P8 阶段顺序固定且可观测；R1~R7 七条规则在 pipeline 中各有对应阶段；P3 复用 P2 通勤图（无半径计算分支） | S-03 / S-04 阶段产物快照 + 代码检查 |
| A4 | 每个 tick 提交自包含 TickSnapshot（含 schemaVersion / configHash / engineVersion / seed / 命令溯源）+ Δ_t + 归因链；每个显著变化 ≥1 条原因 → **支撑 AC2** | S-05 归因完整性单测 |
| A5 | 冷归档保留 ≥3 周期，可查询「2~3 周期前」某次满意度变化的完整归因链（覆盖 D4） | S-05 / S-12 跨周期诊断回归 |
| A6 | tick 级撤销与周期级回退重试均通过「恢复 Keyframe + 丢弃其后 Delta」完成，**代码库无任何逆运算路径**；回退后 tickId 单调递增、链条一致 | S-11 回退一致性单测 + 结构检查 |
| A7 | 32×32 满网格单次结算耗时基准被实测记录（作为「建议 → 硬指标」校准输入，**不预先冻结**） | S-04 / S-12 性能校准报告 |
| A8 | 切后台 / 折屏切换只冻结 + 保存，不推进 tick、不读墙上时钟、不重置模拟状态 | S-01 / S-08 生命周期回归 |
| A9 | 模拟层零平台 / 零渲染依赖、零热路径分配（静态检查） | 代码评审门 G3 检查记录 |
